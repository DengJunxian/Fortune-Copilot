# Fortune Copilot 已知限制与安全边界

## 数据与代表性

- Canonical Persona V2 只有 A-H 八类合成家庭；它们用于验证结构、分支、口径和演示，既不是抽样调查，也不代表中国家庭总体分布。A／B／C 三家庭对照只是兼容的旧 Demo 视图。
- 原组合引擎的 19 项产品映射仍全部为 Mock。新增智能投顾另有 8 只经公开官方证据核验的真实公募基金白名单；它不是工行内部实时货架，不能保证任何时点、地区或客户账户可申购。
- 受控知识是 9 份离线文档/16 个切片的演示库；政策、地区成本和产品事实不会自动联网更新。
- 官方 CPI、家庭通胀、目标成本和最低工资辅助信号均有版本；离线参数不能冒充当前实时统计。

## 模型与算法

- Monte Carlo、收益、波动、相关性、通胀和事件参数是情景假设，不是预测，也不证明未来业绩。
- 100 路径主 Demo用于现场速度和可复现性，不是生产精度结论；生产研究需路径收敛、模型校准和独立验证。
- 行为实验使用合成选择，不能诊断人格、心理疾病或证明干预有效。
- 组合网格和规则降级用于说明可审计决策机制，不替代持牌投研、产品尽调和投资决策委员会。
- LLM 的 Mock/外部兼容层不能提高关键数值权限；模型仍可能解释失败，因此保留模板降级和人工复核。

## 机构与法律

- 项目不是工商银行官方产品。虽然真实基金目录引用工行官网公开列示证据，但仍未接入工行账户、CRM、内部实时产品货架、交易、风控、投诉、电子签名或监管报送系统。
- 模拟账号不是生产身份；客户确认不是法律电子签名。
- 系统不执行交易，不提供个股、杠杆或股指期货默认推荐，不构成法律、税务、保险或证券投资建议。
- 真实落地需要持牌主体、适当性制度、隐私评估、模型治理、双录/留痕、法定留存与人工职责分离。

## 安全与运维

- 默认本地 Demo 签名会话和 SQLite 只适用于竞赛演示；生产必须使用机构密钥管理、SSO、数据库备份、加密和监控。
- 逻辑擦除会保留必要审计标记；真实备份介质删除和法定留存周期尚未实现。
- 可选 PostgreSQL profile 只验证兼容路径，不等于生产高可用、灾备或容量认证。
- 漏洞扫描依赖外部情报；离线模式只能运行静态、单元和行为安全测试，不能获得最新漏洞数据库。

## 效果与评价

- 自动化测试、浏览器回归和黑盒验收只能证明当前测试环境行为；具体数量以最新 `docs/final_test_report.md` 为准。
- Golden Outcomes 与 Release Benchmark V2 是结构性合成回归，不是客户研究、投资回测、生产 SLA、模型认证或银行验收。
- 页面运行时间不是生产 SLA；机器、容器缓存和路径数变化会影响结果。
- 理解度、顾问工时、AUM 留存、转化率、投诉降低和行为改善都没有真实参与者数据；目前只完成合成/授权实验协议。
- 不能用合成家庭结果、历史公开产品资料或竞赛现场反馈推断工商银行实际经营效果。

## 不可突破的表达边界

- 信用卡额度不是资产；
- 四账户不是固定比例；
- “保本的钱”不代表银行理财、信托、基金或保险保本；
- 70% 不适用于家庭总资产，只可能适用于通过全部前置条件的长期可规划资源；
- 最低工资不是 CPI，也不是收益保证线；
- 压力测试不是预测，历史不代表未来；
- 关键金额、比率和配置来自确定性工具，不由 LLM 生成。
