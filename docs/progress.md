# 智运财富 Fortune Copilot 实施进度

最后更新：2026-08-07

## 2026-08-07：客户主流程与基金投顾产品化重构

本轮处理智能投顾接入后出现的信息架构混乱、内部术语外露和客户文案机械化问题。品牌保持“智运财富”，小标题“普慧金融”，英文名“Fortune Copilot”；视觉统一为克制、可信的工商银行金融科技产品风格，同时保留项目自有品牌标识。

### 已实施

- 公开客户案例不再进入 `/client/advanced` 的 11 个内部工作区，统一进入“家庭情况 → 财务报表 → 财务分析 → 目标计划 → 八章规划书”的客户主流程。
- 首页首屏改为“把家庭财务看清楚，再决定下一步”，用住房、养老、子女教育、父母赡养和收入稳定性解释中国家庭动态四账户，不再向客户展示产品设计思路。
- 第七章接入 `FundAdvisoryWorkspace`。具体基金说明只细分已经确定的家庭规划金额，不增加投资本金，也不跳过生活、保障、近期目标和适当性判断。
- 基金投顾按资金用途、本次金额、风险承受范围、家庭准备情况、产品名称与代码、金额、比例、风险和购买前核对逐层展示；产品资料来源默认折叠。
- 客户页面移除“引擎、守门、候选池、Mock、证据链、确定性校验”等内部表达。货币基金、短债基金、纯债基金、宽基指数和个人养老金分别使用面向投资者的用途与风险说明。
- 六项比率的模型提示改为理财规划师当面解释的语气：每项只给一个自然结论、一个需要核对的问题和一个本月可完成的动作，避免重复“表明、需关注、建议”等模板句式。
- 视觉使用暖白底、深墨文字、单一银行红、细分线和账表式数字层级；新增投顾组件的桌面与移动端单列规则，修复长产品名、金额和风险说明可能相互挤压的问题。
- Docker Compose 补齐基金产品目录路径，主 Demo 的具体产品说明接口恢复为 200 响应。
- `DESIGN.md`、前端架构文档和设计审计已同步更新，明确公共客户层、内部工作区与第七章产品说明的边界。

## 2026-08-06：门槛下学习仓、投资者教育与移动端修复

本轮把“尚未达到正式长期配置启动线”和“完全不能开始投资学习”拆成两个状态。正式配置门槛保持不变；满足限定条件的客户可从多余长期资金中拿出小仓位学习宽基指数基金。

### 已实施

- 四账户规则升级到 2.2，新增确定性 `investment_learning` 结果。只有可规划金融净值未达正式启动线、年度新增结余为正、完成前置安排与市场留存后仍有多余长期资金、没有待处理高息债务且通过适当性条件时，才生成学习仓。
- 学习仓上限为“完成前置安排与市场留存后的多余长期资金”的 10%，再由行为承受力系数向下调整；10%不是家庭总资产比例，也不是要求用满的目标。
- Demo A 的多余长期资金为 114,250.00 元，上限为 11,425.00 元，经 0.75 行为系数后建议 8,568.75 元，占 7.5%；Demo B 因无多余长期资金且有待处理高息债务，学习仓仍为 0。
- 第七章新增正式启动线与学习仓的双状态展示，直接列出本次金额、实际比例、10%上限、明确分母和未通过条件；70%正式配置边界继续独立展示，不适用于学习仓。
- 投资建议改为面向客户投资者的分段说明，先解释家庭当下安排，再说明学习仓为什么存在、如何认识宽基指数基金的波动、费率与持有期限，以及何时应降低仓位。
- `redesign-existing-projects` 复核发现移动端双层吸顶会遮挡切换后的章节标题，五步进度还需横向拖动。现已增加章节滚动避让，手机端五步进度改为同屏纵向图标布局，并补齐长文字换行与窄屏卡片降列。

### 验证

- `make check` 全量通过：后端 Ruff、Mypy、92 项 Pytest；前端 ESLint、TypeScript、38 项 Vitest 与生产构建全部通过。
- Docker Compose 已重建并健康运行；前端 `18080`、后端 `18000`。

## 2026-08-06：智运财富品牌、KYC 与中国家庭动态四账户

本轮将对外品牌统一为“智运财富”，副标为“普慧金融”，英文名为“Fortune Copilot”，并把中国家庭四账户从理念说明落实为客户填写、后台计算、模型解释和八章规划书中的同一套产品契约。

### 已实施

- 首页、顶栏、页脚、HTML 标题、API 元信息和正式报告封面完成品牌统一；旧浏览器草稿键继续兼容，避免已有填写内容丢失。
- 基本情况页新增客户识别与投资适当性：地区类型、30万—100万元长期资金启动线、资金来源、投资经验、风险偏好、波动承受、投资期限和个人养老金状态。
- 新增 Alembic `0014_fortune_copilot_kyc`，把客户确认的 KYC 与启动线写入家庭记录；风险能力、意愿、知识和波动承受由确定性评分生成上限。
- 四账户规则此前升级到 2.1：要花的钱只承担小额支付结算；保命的钱坚持保险保障与投资分开；保本的钱服务应急、个人养老金与五年内目标；生钱的钱先检查可规划金融净值与客户启动线。本轮已继续升级到 2.2。

- 保本的钱新增偏积极／中性／偏防守三档确定性市场规则，对应 5%—10%／10%—20%／20%—30% 参考区间及 7.5%／15%／25% 战术锚；只移动满足前置安排后的长期资源，家庭目标和安全约束优先。生钱的钱 70% 只适用于完成日用、保障、近期目标和优先债务后的长期可规划资源，不套用于家庭总资产。

## 2026-08-06：客户理财规划产品化重设计

本轮从真实财富管理产品的客户任务出发，将对外前端收敛为“家庭情况 → 财务报表 → 六项比率 → 目标与大额支出 → 八章规划书”的五步主路径。客户经理、风险、高级客户和完整演示能力作为内部工作区保留，不再占据客户默认导航。

### 已实施的产品能力

- 重写首页与公共顶栏，移除客户可见的技术状态、模拟账号、工程说明和高密度内部导航。
- 新增 `/planning` 主产品入口，`/client` 同步指向新流程，原高级客户工作区保留在 `/client/advanced`。
- 新增个人／家庭基本情况表单，支持多成员、出生日期、职业、收入稳定性和预计退休年龄。
- 新增中国家庭理财常用口径的资产、负债、年收入和年支出表单，支持自定义项、动态增删与草稿自动保留。
- 信用卡只接收未付金额并进入负债，新接口不接收信用卡额度字段。
- 新增客户规划批量录入服务与 `POST /api/v1/wealth-planning/cases`，在同一事务内建立家庭、成员、资产、负债、收入和支出，随后返回确定性分析。
- 新增财务概览、资产结构、年度收支可视化与六项比率分析；每项同时显示公式、代入、范围、含义和家庭分析。
- 新增 `POST /api/v1/households/{household_id}/ratio-explanations`，只把已验证的六项结果交给模型解释，输出再经 Pydantic 结构校验。
- DeepSeek 对接已按 JSON Object 输出模式适配，Docker Compose 可从本地环境变量传入 Provider、模型、基础地址与密钥；仓库不保存密钥。
- 新增理财目标与大额支出动态表单，记录金额、日期、已准备资金、重要程度和计划来源。
- 新增客户阅读版八章规划书，一级目录固定，支持返回修改、打印和保存 PDF；内部正式报告能力继续保留 HTML／PDF 导出。
- 第七章当前仅给家庭资金使用顺序与风险边界，不过度设计尚未交付的智能投顾能力。
- 首页新增单身职场新人、双收入三口之家、临近退休夫妻三类真实人物形象，每个案例均能进入完整规划流程。
