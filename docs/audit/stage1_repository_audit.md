## 缺口清单

1. 缺少可运行的客户端、顾问端和风险端。
2. 缺少 API 版本化、错误模型、日志、配置和数据库连接。
3. 缺少 SQLAlchemy、Alembic 以及 SQLite/PostgreSQL 双运行路径。
4. 缺少 LLM Provider 边界和无 Key Mock 模式。
5. 缺少唯一视觉规范、来源锁、设计 token、组件和无障碍约束。
6. 缺少 Pytest、Vitest、Playwright、Lint、类型检查和构建门禁。
7. 缺少 Docker Compose、一条命令启动和 CI。
8. 缺少领域模型、确定性财务计算、四账户瀑布、目标规划、适当性、数字孪生、行为金融、RAG、报告和审计链。这些属于提示词 2-14，不能在阶段 1 伪装为已实现。

## 风险清单

| 风险 | 影响 | 阶段 1 处理 |
| --- | --- | --- |
| 空仓范围过大 | 容易一次堆积不可验证代码 | 先建立最小可运行垂直底座，按提示词顺序增量扩展 |
| 金融文案误导 | 可能把比例、产品或授信表达错误 | 将七项核心红线固化到 API 能力清单、README、设计规范和风险端 |
| LLM 越权计算 | 关键金额可能不可审计 | Provider 抽象只提供语言输出，Mock 明确 deterministic_tools_only |
| 外部模型或网络不可用 | 现场 Demo 中断 | 默认 Mock Provider、SQLite、前端离线能力清单 |
| API Key 泄露 | 凭证进入仓库或日志 | 只读取环境变量，.env 被忽略，示例不含密钥 |
| PostgreSQL 不可用 | 本地启动受阻 | SQLite 为默认，PostgreSQL 作为可选 profile |
| 外部设计资源漂移 | 规范不可追溯 | 锁定实际 HEAD、许可证、读取文件和本地快照 |
| 复制外部品牌 | 品牌混淆或许可证风险 | 仅提取原则，生成 Fortune Copilot 自有 DESIGN.md 和 token |
| 未实现能力穿帮 | 比赛演示可信度下降 | 能力接口区分 real、mock、mock_only、none |
| 浏览器或容器环境差异 | 本地通过但 CI 失败 | Python 3.12、Node 22、Docker 镜像和 CI 统一版本 |

## 阶段 1 实施基线

- 技术栈采用提示词推荐架构，因为仓库没有既定栈。
- 后端关键金融模块只预留目录和契约，不提前写不可验证的业务数字。
- 前端展示方法顺序、能力边界和三端入口，不展示伪造家庭财务结果。
- 设计协议按空仓 Scan、Diagnose、Fix 执行，结果记录在 docs/design/client_ui_audit.md。
- 任何外部模型连接均默认关闭。用户提供的密钥未写入仓库。
