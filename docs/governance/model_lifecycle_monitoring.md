# 模型生命周期、漂移与公平性监控

国家金融监督管理总局的[银行保险机构数据安全管理办法](https://www.nfra.gov.cn/cn/view/pages/governmentDetail.html?docId=1192311&generaltype=1&itemId=861)要求 AI 模型统一管理、可验证、可审核、可追溯，并在上线前进行数据安全和可解释性审查，保留退出 AI 的替代方案。2026 年发布的[银行业保险业人工智能安全开发应用指导意见](https://www.nfra.gov.cn/cn/view/pages/governmentDetail.html?docId=1261784&generaltype=1&itemId=)进一步覆盖需求、数据、训练、部署、维护、评价和退出全生命周期。

Fortune Copilot 的模型治理门禁接受已经聚合的监控指标，不接收客户级样本：

- 总体与最小群体样本量；
- 输入和输出漂移；
- 群体公平性最大差异；
- 无依据事实率；
- 可用性；
- 独立验证、数据安全、可解释性审查、批准编号和基线版本。

阈值按模型风险等级收紧。任一控制失败均返回 `block`，并要求切换本地确定性回退。评估写入审计事件，但接口返回的结果只是对调用方汇总指标的规则判断，不能代替工行独立验证报告或生产批准。

无论模型是否通过，允许任务仍限于信息提取、受控 RAG、解释和报告表达。金额、比例、市场状态、适当性、产品资格和交易决定仍由确定性规则或银行权威系统完成。
