# 生产就绪、SRE、灾备与全渠道

## 两种就绪语义

- 开发／比赛环境：`/health/ready` 只判断当前本地服务是否可以承载合成数据演示。
- 生产环境：除数据库外，所有银行专有集成、模型治理和运维控制都必须满足；否则返回 HTTP 503。

因此，本地返回 `status=ready` 与 `/integrations/readiness` 返回 `production_ready=false` 可以同时成立。前者说明 Demo 可运行，后者明确说明尚不能服务真实客户。

## 生产硬门槛

1. 银行身份、客户授权、CDD/EDD/AML 与最小权限。
2. 真实账户、产品、交易、CRM 和投研委员会端口。
3. 经批准的 RTO/RPO、备份介质、定期恢复和灾备切换演练。
4. 网络隔离、密钥设施、容量与性能基线、指标／日志／追踪和告警值班。
5. 数据库高可用、幂等、对账、消息恢复和故障注入验证。
6. 手机银行、网银、网点、客户经理等渠道的身份、权限、可访问性和发布验收。

当前 Docker Compose、SQLite/PostgreSQL 支持、健康探针和本地备份命令只证明原型具备可测试的运维接口，不能作为银行级高可用或灾备证据。所有尚缺项通过 `/api/v1/integrations/readiness` 逐项暴露，避免在部署文档或界面中把“设计完成”写成“已经投产”。
