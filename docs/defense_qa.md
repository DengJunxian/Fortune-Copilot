# 智运财富 Fortune Copilot 答辩高频问题

版本：1.0  
核验日：2026-08-05  
统一边界：竞赛原型、合成数据、Mock 接口、非工商银行官方产品；不提供交易执行，不承诺本金或收益。

## 1. 这是否只是“标准普尔四象限”的本土化换名？

不是。相似处只是都用用途账户帮助用户理解资金。Fortune Copilot 的计算核心是“中国家庭目标—约束—账户—产品—行动”：成员责任和六阶段决定基础参数，目标按日期和专项成本计算，七步瀑布先处理债务、应急、保障和近期目标，三道适当性闸门再决定长期资金能否进入产品候选。四账户金额不是固定比例。

可验证证据：`GET /api/v1/demo/families/comparison` 对 A/B/C 返回 3 个不同 `configuration_signature`，并返回 `fixed_ratio_model=false`；规则与公式见 [规划引擎](planning_engine.md)，后端回归见 `backend/tests/test_planning.py` 与 `backend/tests/test_demo_release.py`。

## 2. “生钱账户 70% 以上”是否过于激进？

如果分母是家庭总资产，确实是错误且危险的表达。本系统中的 70% 不是默认建议，只是一个有条件的结果标识：五项硬约束全部通过、行为未下调、年度结余为正、前置层完成且存在真实长期资金时，长期增长金额占“扣除优先债务后的可规划资源”才可能达到 70%。

未达到正式启动线的客户不会套用 70%。如果仍有正结余、无待处理高息债务、前置安排后存在多余长期资金且通过适当性条件，系统只允许以不超过该多余长期资金 10% 的小仓位学习宽基指数基金；10% 是上限，也不是家庭总资产比例。

主 Demo B 因应急、保障和近期目标不足，长期新增金额为 0.00 元，而不是 70%。接口同时返回家庭总资产、可投资金融资产和年度新增结余三种分母；测试锁定分母与前置条件，见 [规划引擎](planning_engine.md#三尺参考带与-70-条件) 和 `data/expected/demo_b_planning_v1.json`。

## 3. 为什么账户叫“保本的钱”，却不代表所有产品都保本？

“保本的钱”是客户容易理解的资金用途名称，表达本金安全与流动性目标；具体产品是否保证本金只能依据合同属性判断。银行理财、信托、基金和保险不能统一描述为保本产品，因此系统仍会逐项检查净值、风险、期限、流动性、费用、保证利益和非保证利益。

实现证据：19 项 Mock 产品逐项建模，家庭/客户/产品三道闸门决定是否仅教育展示、拒绝或可进入人工审核；禁语由可信 AI 终检和报告发布门禁检查，见 [组合与适当性](portfolio_engine.md)、[可信 AI](trusted_ai.md) 与 `backend/tests/test_portfolio.py`。

## 4. 为什么最低工资不能直接等同通胀？

两者衡量对象不同：最低工资是劳动报酬法定底线和基本生活保障制度，CPI 衡量消费价格变化。最低工资还受地区、就业和政策调整影响，不能替代官方 CPI、家庭支出加权通胀或教育/医疗/养老专项成本。

系统把四种购买力口径分开，并把最低工资标记为 `is_cpi=false`、`is_return_guarantee=false`。受控知识、数据字典、前端和治理终检都拒绝“最低工资等于 CPI”的声明，测试见 `backend/tests/test_financial_engine.py` 与 `backend/tests/test_trust.py`。

## 5. 大语言模型会幻觉，为什么系统还能可靠？

系统不把关键金融计算交给模型。LLM 只负责自然语言理解、追问和受控解释；金额、比率、目标现值、账户、组合、概率和报告数字由 `Decimal` 纯函数、规则引擎和固定 seed 模拟生成。模型输入先做字段白名单与脱敏，输出必须通过 JSON Schema/Pydantic；失败自动退回本地模板。

九智能体是固定状态机，每一步有工具白名单和禁令，最终还会检查数字账本、政策有效期、产品版本和提示注入。8 类对抗评测与 10 项发布门禁均有持久化结果，见 [模型卡](model_card.md)、[评测说明](evaluation.md) 与 `backend/tests/test_security_privacy.py`。

## 6. “家庭财富数字孪生”是否只是包装？

不是。它有明确状态、更新顺序、公式和可复现输出：逐月更新收入、支出、资产、债务、保障、养老金、目标和家庭事件；使用固定 seed、相关矩阵与 Cholesky 生成路径；输出五个分位数、目标成功、首次失败、耗尽、被迫出售和最差路径。基线与方案使用共同随机数。

19 个场景、任务进度、取消竞态、参数哈希和导出均已实现。主 Demo 的 100 路径标准答案独立保存在 `data/expected/demo_b_twin_v1.json`，运行时不读取；实现和测试见 [数字孪生引擎](twin_engine.md) 与 `backend/tests/test_twin.py`。这些仍是条件模拟，不是预测。

## 7. 没有工行真实数据，如何证明项目有效？

目前只能证明“工程机制有效”，不能证明“真实业务效果有效”。已证明的包括：同一规则对三套家庭输出不同方案、关键公式对独立标准答案、三端状态不可跳步、违规请求被拒绝、离线 Demo 可运行、备份可恢复、报告数字可追踪。

理解度、客户经理工时、AUM 留存、转化和行为干预效果目前只是协议就绪或业务假设，没有写成工行真实指标。下一步应先做脱敏影子运行，与持牌客户经理的人工结论对照；通过治理后再做小范围、授权、可退出的试点。见 [实验与性能](performance_experiments.md) 和 [最终测试报告](final_test_report.md)。

## 8. 这会不会构成无牌投顾？

比赛版不接真实客户、不执行交易、不销售产品、不生成可直接下单的个性化证券指令。组合只使用 Mock 产品和教育性/待审核状态，普通家庭默认不推荐个股、杠杆或期指；重大决定必须由持牌主体按适当性和人工流程复核。

如果未来进入真实机构，主体资质、业务牌照、产品销售边界、投资者适当性、双录/留痕、合同与电子签名都必须由工行法务、合规和业务部门确认。原型中的“客户确认”只保存脱敏演示签署，明确不是法律电子签名。见 [三端审核契约](review_workflow.md) 与 [安全隐私](security_privacy.md)。

## 9. 如何证明方案真的“因人而异”？

不是比较页面换名字，而是比较由各户事实实时计算的签名。A/B/C 的生命周期、动态安全月数、房产集中、保障缺口、目标期限、四账户金额和长期可用金额均不同；`unique_configuration_count=3` 是黑盒验收项。

进一步可以用反事实接口只改变一个条件，例如补应急金、减少高息债务、延后目标或提高月结余，系统会保持资源守恒并返回变化表。测试见 `backend/tests/test_planning.py`、`backend/tests/test_demo_release.py`，实测入口为 `/demo` 的三家庭对照。

## 10. 如何证明系统有效，而不是只证明代码能跑？

应分四层回答：

1. **计算有效性**：独立标准答案、Decimal、边界测试与版本哈希；
2. **流程有效性**：三端不可跳步、对象权限、人工复核与发布门禁；
3. **可用性**：Playwright 主路径、键盘/读屏语义、离线和降级状态；
4. **业务有效性**：仍需真实授权试点，不能用合成指标替代。

当前仓库对前三层提供自动化证据；第四层在功能矩阵中标为“计划/需机构验证”。系统不以回测收益或合成转化率冒充效果。

## 11. 与工行“AI投”、且慢、蚂蚁财富、Betterment、Wealthfront 有什么差异？

只比较官方公开描述的产品重心，不做优劣排名，也不声称这些产品当前功能边界永远不变。

| 产品/公开能力 | 官方公开重心 | Fortune Copilot 的研究重心 | 不应得出的结论 |
| --- | --- | --- | --- |
| 工行“AI投” | 历史官网页面描述按风险等级、期限推荐基金组合并支持一键投资/调仓 | 先做完整家庭资产负债、保障、目标、行为与三端治理，再进入 Mock 产品 | 不能由历史页面推断当前在售；不能声称已接入工行 |
| 且慢 | 官方内容体现基金投顾组合、跟调、陪伴和风险揭示 | 动态四账户、家庭数字孪生、顾问—合规—客户证据链 | 不能声称 Fortune Copilot 投资能力优于且慢 |
| 蚂蚁财富 | 官方材料强调机构开放平台、用户连接/画像、AI 选品与金融助理 | 银行内部家庭综合金融工作台与确定性计算治理 | 不能拿平台规模或用户数据作本项目成绩 |
| Betterment | 官方说明涵盖现金管理、目标型 ETF 投资和退休规划 | 中国家庭住房/负债/保障/养老语境与本土合规闭环 | 美国监管、税务和账户体系不能直接照搬 |
| Wealthfront | 官方页面强调自动化、分散指数投资、目标和风险定制 | 家庭安全约束、行为证据、受控政策与三端审核 | 不能用其公开收益展示为本项目收益基准 |

公开来源：[工行 AI投](https://www.icbc.com.cn/icbc/gxk_1/12686.htm)、[且慢投顾服务说明](https://content.qieman.com/items/20419)、[蚂蚁财富开放 AI](https://www.antgroup.com/news-media/press-releases/1497610023452)、[Betterment 服务说明](https://www.betterment.com/help/what-is-betterment)、[Wealthfront 自动化投资](https://www.wealthfront.com/)。核验日为 2026-08-05。

## 12. 数据隐私和消费者保护怎么做？

数据按场景授权，敏感保障授权单列；客户可以导出、撤回授权、申请逻辑擦除和人工复核。角色会话绑定家庭对象范围，高风险操作要求二次确认。日志和模型台账只存脱敏摘要、哈希、版本和请求 ID，不复制完整财务载荷。

消费者保护不是报告末尾一句免责声明，而是进入计算前的适当性硬约束、生成中的禁令、发布前门禁和发布后的投诉回放。客户不能读取合规前内部报告；风险端能看到控制理由、规则、来源和版本。删除为可审计逻辑擦除，真实生产的备份删除、法定留存和监管报送仍需机构制度确定。

## 13. 工行为什么需要它，价值是否只是“促进销售”？

不是。可验证的产品价值主张包括：把存款、贷款、保险、养老金、基金与理财放入同一家庭目标账本；提高客户经理准备、解释和复盘的一致性；让风险合规获得公式、版本、引用与投诉回放；让客户看懂风险和下一步行动。潜在业务价值包括资产留存、养老金融、综合服务与长期陪伴，但必须通过真实授权试点验证。

系统刻意禁止用短期转化率压过适当性：安全层未通过时只能教育展示，产品不匹配会拒绝，客户行为只能下调风险上限，发布失败不会被隐藏。这些机制更接近长期客户关系和消费者保护，而不是一次产品销售。

## 14. 为什么不默认推荐个股、杠杆或股指期货？

普通家庭的首要风险通常是现金流、负债、目标期限和行为偏差，而不是缺少高风险工具。个股集中、杠杆和期货会放大尾部损失、流动性和操作风险，也可能超出客户知识与专业条件。

系统默认使用指数化、分散化和低成本长期方向；5% 战术偏移只在安全闸门通过后、仅在固定收益和宽基权益之间有限调整。杠杆、集中个股和普通家庭专业期货请求是固定对抗用例，必须拒绝并留下审计证据。

## 15. 断网、模型故障或银行接口不可用，现场会不会失效？

不会影响主 Demo。默认运行栈只有浏览器、FastAPI、SQLite、本地 JSON 规则/知识和 Mock LLM；没有 CDN、外部字体、行情和外部模型依赖。八类银行接口本来就是 Mock。模型失败会退回模板解释，确定性计算继续运行。

`make acceptance` 明确检查 `mock_mode=true`、`external_network_required=false` 和外部调用数 0；Compose 健康、备份恢复和浏览器主路径均有实测记录。若浏览器页面局部失败，`/demo` 已持久化十阶段摘要和三端入口，演示风险预案见 [演示风险预案](demo_risk_plan.md)。
