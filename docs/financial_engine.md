# 确定性财务引擎

版本：`financial-metrics-v1.0.0`  
规则：`financial_health@1.0.0`  
阶段：提示词 3

## 计算边界

引擎只读取当前家庭的有效事实记录，转换为不可变领域事实，再用 `Decimal` 和纯函数计算。语言模型不在依赖图中，既不能给出金额和比率，也不能改写阈值或适用性。GET 分析不写数据库；用户显式保存时才持久化完整快照、20 项指标和一条不含完整财务载荷的审计事件。

固定顺序如下：

1. 家庭基础情况；
2. 资产负债表；
3. 现金流量表；
4. 保险保障表；
5. 目标资金表；
6. 资产流动性矩阵；
7. 数据诊断、四类保障缺口和四重购买力；
8. 20 项独立指标与七维辅助视图（流动性、偿债、储蓄、保障、分散、养老、目标）。

信用卡额度始终不计入资产；信用卡未付余额计入负债。定期存款与银行理财、自住房与投资性房产分别分类。保险保额和非保证利益不计入资产，保费进入现金流；现金价值只有作为独立 Asset 事实存在时才进入资产表，从而避免重复计算。

## 五张底表与诊断

| 输出 | 核心口径 |
| --- | --- |
| 资产负债表 | 当前有效资产市值、未偿负债余额、净资产与会计恒等式 |
| 现金流量表 | 逐项年化收入／支出、结余、基本生活、必要、固定、债务偿付和保费口径 |
| 保险保障表 | 有效保单、保额、保费、免赔额、保证／非保证利益与现金价值，附防重复说明 |
| 目标资金表 | 目标金额、最低可接受金额、已准备、缺口、期限、刚性与成本增长率 |
| 流动性矩阵 | 即时、30 日内和一年内变现能力；分别标注是否计入应急和短期覆盖 |

诊断检查核心资料缺失、可能重复资产、质押资产未关联负债、收入支出矛盾、异常资产变化、过期／缺失估值日期、债务偿付对账、保费对账和高息债务。完整度是 0–100 分的内部数据质量提示，不是 0–1 比率或监管评级。

## 指标清单

| metric_id | 中文名称 | 公式 | 单位 |
| --- | --- | --- | --- |
| total_assets | 家庭总资产 | 所有已确认资产市值之和，不含信用卡额度 | CNY |
| total_liabilities | 家庭总负债 | 所有未偿负债余额之和 | CNY |
| net_worth | 家庭净资产 | 家庭总资产 − 家庭总负债 | CNY |
| liquidity_reserve_months | 流动储备月数／应急储备月数 | 即时可用金融资产 ÷ 月基本生活支出 | months |
| short_term_debt_coverage | 短期偿债覆盖率 | 30 日内可变现金融资产 ÷（未来 12 个月合同应付债务 + 刚性目标缺口） | ratio |
| debt_to_asset_ratio | 负债比率／资产负债率 | 家庭总负债 ÷ 家庭总资产 | ratio |
| savings_ratio | 结余比率 | 年度税后结余 ÷ 年度税后总收入 | ratio |
| debt_service_burden_ratio | 财务负担率／偿债负担率 | 年度债务本息支出 ÷ 年度税后总收入 | ratio |
| investable_assets_to_net_worth | 投资与净资产比率 | 可投资金融资产 ÷ 家庭净资产 | ratio |
| property_to_assets_ratio | 房产与资产比率／房产集中度 | 房产总价值 ÷ 家庭总资产 | ratio |
| housing_equity_to_net_worth | 住房净权益占净资产比例 |（房产价值 − 相关房贷余额）÷ 家庭净资产 | ratio |
| twelve_month_liquidity_coverage | 12 个月流动覆盖率 | 一年内可变现金融资产 ÷（年度必要支出 + 一年内刚性目标缺口） | ratio |
| fixed_expense_ratio | 固定支出率 | 年度必要／刚性支出 ÷ 年度税后总收入 | ratio |
| protection_coverage_ratio | 保障覆盖率 | 最大不可承受风险的现有保障 ÷ 所需保障 | ratio |
| protection_gap | 保障缺口 | 最大单一不可承受风险所需保障 − 对应现有保障 | CNY |
| retirement_funding_adequacy | 养老资金充足率 |（养老已准备与养老金资产较大值 + 社保余额）÷ 养老目标金额 | ratio |
| goal_funding_ratio | 目标准备率 | 全部目标已准备资金 ÷ 全部目标金额 | ratio |
| income_concentration_hhi | 收入集中度 HHI | Σ（单一收入来源 ÷ 年度总收入）² | hhi |
| product_hhi | 产品集中度 HHI | Σ（单项可投资金融资产市值 ÷ 可投资金融资产总额）² | hhi |
| financial_independence_ratio | 财务自由度 | 可持续非劳动性年度收入 ÷ 年度总支出 | ratio |

“介于比率”按需求上下文锁定为 `savings_ratio` 结余比率。投资与净资产比率不采用“越高越好”规则。产品 HHI 继续以家庭已有可投资 Asset 记录作为持仓代理；Stage 5 的 Mock 产品目录只用于候选映射，不会反向伪造家庭已有产品持仓。

每个结果都返回 `metric_id`、中文名、公式、实际代入、输入及来源记录、结果、分子、分母、单位、阈值版本、状态、解释键、数据日、计算来源、适用性、参考条件、参考来源、模板解释和至少一项行动。分母为零或净资产不满足定义时返回 `null + not_applicable`，绝不伪装为 0。

## 保障与购买力

保障模型分别计算身故责任、医疗自付、意外收入中断和家庭责任，按最大单一不可承受风险报告主要缺口，避免跨场景重复相加。输出需求、现有覆盖、覆盖率、缺口、优先级、依据和保费压力，不推荐具体保险产品。

购买力输出四个互不替代的口径：官方 CPI 口径的离线 Demo 参数、按家庭支出权重计算的个性化消费通胀、逐目标成本增长和最低工资追赶参数。当前 CPI 数值明确是 `internal_demo`，不冒充实时官方发布；最低工资参数明确不是 CPI，也不是收益保证线。

## API 与持久化

- GET `/api/v1/households/{id}/financial-analysis`
- GET `/api/v1/households/{id}/statements`
- GET `/api/v1/households/{id}/metrics`
- GET `/api/v1/households/{id}/diagnostics`
- GET `/api/v1/households/{id}/financial-analysis/export`
- POST `/api/v1/households/{id}/financial-analysis/runs`

所有接口可传 `analysis_date=YYYY-MM-DD` 以复现实验。JSON 导出包含完整分析和版本元数据。保存运行关联 RuleVersion，保存 input SHA-256 和完整分析快照，并将指标适用性、公式／阈值版本及证据分项落库。

## 已验证边界

- 零收入：收入分母指标不适用，不返回假 0；
- 负净资产：净资产与相关比率进入 critical／not_applicable；
- 无房产：房产集中度为 0，住房净权益比不适用；
- 波动收入：应急区间切换为 6–12 月；
- 多套房：自住与投资性房产分别计入并汇总；
- 缺失、重复、过期记录：生成诊断问题与行动；
- Decimal：金额保留分，比例保留六位，展示舍入使用 ROUND_HALF_UP；
- 无模型、无银行接口、无网络：SQLite、合成事实、Mock LLM 和本地规则完整运行。
