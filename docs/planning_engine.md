# 目标规划与动态四账户引擎

版本：`fortune-copilot-four-account-v2.2.0`  
规则：`dynamic_account_waterfall@2.2.0`  
阶段：提示词 4

## 计算边界

本引擎只读取当前家庭的有效事实、提示词 3 的确定性财务底表和本地版本化规则。目标未来金额、现值、缺口、月投入、四账户金额与比例、反事实差额全部用 `Decimal` 计算，不调用 LLM。

四账户是顺序式资金瀑布，不是家庭总资产固定比例：

1. 要花的钱：日常支付、应急储备与一年内确定支出；
2. 保命的钱：必要年保费与保障缺口分开表达；
3. 保本的钱：一至五年目标、债务缓冲和安全留存；
4. 生钱的钱：正式配置使用通过完整约束后的真实长期资金；正式启动线以下只有符合限定条件的小额宽基指数学习仓。

信用卡可用额度没有资产字段，不进入流动性或可规划资源；信用卡未付只作为负债并按高息债务优先处理。保额不是资产，保费不是保额，保障缺口不按家庭总资产比例反推。

## 六阶段生命周期

系统结合成员年龄、家庭关系、未成年子女、持续劳动／经营收入、养老金或退休状态、预计退休年龄，识别初入职场、婚姻组建、育儿成长、家庭成熟、退休准备、养老传承六阶段。

API 同时返回 `detected_stage`、`recorded_stage`和 `effective_stage`。默认采用家庭已记录阶段，客户可用 `lifecycle_override` 显式模拟其他阶段。阶段只提供基础安全月数，不会覆盖家庭的实际收入、债务、目标和保障事实。

动态安全月数为：

```text
clamp(
  生命周期基础月数
  + 单／双收入修正
  + 收入稳定度修正
  + 收入波动修正
  + 房贷修正
  + 未成年子女修正
  + 赡养修正
  + 健康风险修正,
  3, 12
)
```

每个修正项返回观测值、月数差和来源记录 ID。

## 目标计划

目标金额按“今日购买力口径”录入，每个目标独立保存成本增速。Demo 现值折现率为年化 2%，来自 `internal_demo` 规则，不是收益承诺。

```text
未来金额 = 今日目标金额 × (1 + 年成本增速 / 12) ^ 剩余月数
现值       = 未来金额 ÷ (1 + Demo 年折现率 / 12) ^ 剩余月数
缺口       = max(0, 现值 - 已准备金额)
月投入     = 缺口 ÷ max(1, 剩余月数)
年投入     = 月投入 × 12
```

同时计算“最低可接受金额”的现值与缺口。当全部目标月投入超过当前可持续新增结余时，返回降到最低可接受金额、延期可延期目标、提高月结余三类可执行调整，并继续显示未解决缺口。

## 七步资金瀑布

分配顺序固定，金额不固定：

1. 高息债务处理；
2. 日常资金；
3. 应急储备；
4. 必要保障成本；
5. 一年内确定支出；
6. 一至五年刚性目标；
7. 剩余长期资金。

可规划资源只包含可投资金融资产与年度新增结余。住房、车辆、投资性房产、社保和养老金账户不会被默认抽取到资金池。年度结余已扣除已记录保费，引擎先加回年保费，再在第 4 步独立分配，从而既不遗漏也不重复扣减。

```text
日用目标 = 月必要支出 × 动态安全月数
           + 12 个月内刚性大额目标现值缺口
           - 可确定用于该目标的同期新增结余

保本目标 = 一至五年刚性目标现值缺口 + 债务缓冲
原始增长 = max(0, 可规划资源 - 债务 - 日用层 - 保障成本 - 保本目标层)
市场战术留存 = min(原始增长, max(0, 可投资金融资产 × 当期战术锚 - 已分配保本资金))
市场调整后增长 = 原始增长 - 市场战术留存

门槛下学习仓上限 = 市场调整后增长 × 10%
门槛下学习仓建议 = 学习仓上限 × 行为承受力系数
```

同期确定结余一旦用于 12 个月内目标，会记入 `same_period_cashflow_committed` 并从后续可分配资源中扣除，不会在目标和增长账户中重复使用。

正式启动线以下的学习仓只在以下条件同时成立时出现：年度新增结余为正、市场调整后仍有多余长期资金、没有待处理高息债务、长期投资适当性条件通过。流动性、保障和五年内目标仍在瀑布前置层按建议金额完整留存；学习仓不从这些用途抽取资金。10%是上限，行为承受力只能继续下调。学习仓用于认识宽基指数基金的波动、费率和持有纪律，不是短期收益目标。

## 三尺、参考带与 70% 条件

每个账户的当前金额、目标金额和建议金额都由后端同时返回三种比例：

- 占家庭总资产；
- 占可投资金融资产；
- 占年度新增结余。

“保本的钱 5%—30%”是分母明确为“可投资金融资产”的总观察带。投研规则以版本化参数发布三档口径：偏积极 5%—10%、中性 10%—20%、偏防守 20%—30%，对应战术锚为 7.5%、15%、25%。引擎只从完成目标与安全安排后的原始长期资源中补足战术锚；一至五年目标、债务缓冲或安全留存需要更多资金时，动态金额优先。该口径不代表任何产品保本或保收益。

市场档位由财富管理投研规则统一发布，不接受客户输入，也不交由大语言模型判断。当前 Demo 规则使用中性档位；未来接入真实市场数据后仍应先由投研治理流程形成受控规则版本。

正式长期配置超过 70% 只能在以下条件全部成立时显示：

1. 流动性、偿债、保障、期限、适当性五项硬约束全部通过；
2. 行为承受力没有下调增长建议；
3. 年度新增结余为正；
4. 前置层完成后仍有真实长期资金；
5. 增长建议占“扣除优先债务后的可规划资源”达到 70%。

该分母不是家庭总资产。70% 条件不适用于门槛下学习仓。正式启动线已达到但其他硬约束未通过时，原始长期剩余最多只能使用可规划资源的 20% 作为阶段性增长上限；正式启动线未达到时只执行前述不超过多余长期资金 10% 的学习规则。其余资金回流稳健安全留存，行为承受力只能继续下调。

## 反事实与资源守恒

反事实支持补足应急金、偿还高息债务、改善保障缺口、提高每月结余、增加目标已准备金额、延后可延期目标和人工覆盖生命周期。

- 补足应急金和增加目标已准备金额是对现有可投资金融资产的重新归类，不新造财富；两者合计不能超过可投资金融资产。
- 偿还高息债务会同额消耗可规划资源，不只修改负债显示。
- 提高月结余才会生成额外年度新增资源。
- 改善保障缺口只表示保障结果变化，不假设产品或保费；Stage 5 产品闸门仍会独立核验产品适当性与持续金额条件。

返回的变化表只比较同一规则版本下的基线与场景，不使用客户情绪或大语言模型生成追涨杀跌信号。市场战术档位是受控规则输入，不得推翻短期目标与安全闸门。

## API 与持久化

- GET `/api/v1/households/{id}/planning`：无副作用计算基线；
- POST `/api/v1/households/{id}/planning/counterfactual`：返回基线、反事实场景和变化表；
- GET `/api/v1/households/{id}/planning/export`：导出完整 JSON；
- POST `/api/v1/households/{id}/planning/runs`：显式保存一个 `draft` Recommendation、四条 AccountBucketPlan、行动项与 `recommendation_generated` 审计事件。

所有结果包含 input SHA-256、公式版本、规则代码与语义版本、分母、实际代入、约束证据和来源记录 ID。GET 不写库；只有显式保存操作会创建草稿与审计事件。

## 已验证边界

- A／B／C 三家庭的四账户签名互不相同；
- A 家庭未达正式启动线，但在通过学习仓条件后只使用多余长期资金的 7.5%，低于 10% 上限；B 家庭无多余长期资金且有高息债务，学习仓为 0；
- 两年内购房目标会提高稳健目标金额；
- 应急金不足时，长期增长不会获得全部新增资金；
- 信用卡额度不进入资产，信用卡未付进入高息债务；
- 70% 只在五项硬约束、行为修正、正结余与长期资金同时通过后出现；
- 12 个月内确定现金流只使用一次，账户金额与已承诺现金流之和保持资源守恒；
- 过大债务减少、保障改善或资产重分类请求返回 422，不负数或新造资源；
- 无外部模型、无真实银行接口、无网络时，SQLite、合成家庭、本地规则和 Mock LLM 仍可完整运行。
