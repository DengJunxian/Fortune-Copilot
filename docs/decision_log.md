# 决策日志

## ADR-001：空仓采用推荐 Monorepo 技术栈

- 日期：2026-08-04
- 状态：已采纳
- 决策：React、TypeScript、Vite 前端；FastAPI、Python 3.12、SQLAlchemy 2.x、Alembic 后端；SQLite 默认、PostgreSQL 可选。
- 原因：仓库无既定实现，提示词已给出明确推荐；该组合支持类型、OpenAPI、Decimal 领域建模和离线 Demo。
- 影响：前后端独立构建，通过 /api/v1 契约集成。

## ADR-002：Mock 和 SQLite 是默认运行路径

- 日期：2026-08-04
- 状态：已采纳
- 决策：主 Demo 不以外部模型、真实银行接口、PostgreSQL 或网络为前置条件。
- 原因：现场可靠性和提示词红线要求。
- 影响：能力接口必须明确 real、mock、mock_only、none；外部服务故障不能中断核心计算。

## ADR-003：语言模型不拥有金融计算权

- 日期：2026-08-04
- 状态：已采纳
- 决策：LLM Provider 只生成语言和结构化理解；关键金额、比率、配置、模拟与适当性由确定性服务完成。
- 原因：可复现、可解释、可审计与金融消费者保护。
- 影响：Mock 输出显式声明 calculation_source 为 deterministic_tools_only；后续外部 Provider 也不得绕过。

## ADR-004：根 DESIGN.md 是唯一视觉规范源

- 日期：2026-08-04
- 状态：已采纳
- 决策：研究 IBM、Revolut、Linear 和 taste-skill 后生成原创 Fortune Copilot 规范，不安装外部品牌组件作为运行时依赖。
- 原因：三端需共享设计语言，又不能复制品牌或依赖网络。
- 影响：页面只引用 frontend/src/styles/tokens.css 与项目自有组件。

## ADR-005：阶段 1 不伪造业务结果

- 日期：2026-08-04
- 状态：已采纳
- 决策：在确定性引擎和合成家庭尚未进入前，前端只展示方法顺序、能力状态和合规边界。
- 原因：避免把展示数字误当成程序计算或工行真实数据。
- 影响：家庭金额和比例从提示词 2-4 开始由代码产生后才展示。

## ADR-006：密钥只从运行环境注入

- 日期：2026-08-04
- 状态：已采纳
- 决策：不把用户提供的 DeepSeek API Key 写入仓库、文档、测试、镜像或日志。
- 原因：提示词和安全基线要求仓库不得提交密钥。
- 影响：后续启用 DeepSeek 时通过 LLM_API_KEY 等环境变量注入；当前阶段不需要外部 API。

## ADR-007：金额采用 Decimal 且 API 拒绝二进制浮点

- 日期：2026-08-04
- 状态：已采纳
- 决策：所有货币字段使用 `Numeric(20, 2)`／Python `Decimal`；API 金额只接受十进制字符串或整数。
- 原因：JSON 浮点无法可靠表示金融小数，静默舍入会破坏可复现性和审计。
- 影响：传入 `100.01` 这类 JSON number 会返回 422；客户端应发送 `"100.01"`。

## ADR-008：领域记录统一采用乐观版本和软删除

- 日期：2026-08-04
- 状态：已采纳
- 决策：初始 28 个领域实体及后续新增的适当性实体共享版本、来源、确认状态、时间戳和软删除字段；PATCH／DELETE 必须携带预期版本。
- 原因：方案与家庭事实需要可追踪变更，避免并发覆盖和历史证据被普通删除接口抹除。
- 影响：陈旧写入返回 409；普通读取隐藏已删除记录；物理删除仅用于受控合成数据重置和数据库级联测试。

## ADR-009：所有嵌套引用必须受家庭聚合边界约束

- 日期：2026-08-04
- 状态：已采纳
- 决策：成员、抵押资产、投保人等外键在 API 和种子导入层验证属于当前 Household。
- 原因：单靠外键只能保证记录存在，不能阻止跨家庭资料误关联。
- 影响：跨家庭引用返回业务错误；Stage 10 已加入四角色端点／动作权限，真实身份鉴别与客户归属仍需在提示词 12 加入行级授权。

## ADR-010：合成家庭是版本化事实输入，不保存预期计算答案

- 日期：2026-08-04
- 状态：已采纳
- 决策：A／B／C 三套数据保存家庭明细、问卷和授权；主 Demo B 的净资产与比率不写入种子。
- 原因：提示词要求关键金额和比率由确定性工具产生，避免用硬编码答案冒充计算。
- 影响：Stage 2 只校验输入总额与结构；Stage 3 必须从相同明细和规则版本推导指标。

## ADR-011：财务体检采用五表优先、纯函数指标和显式持久化

- 日期：2026-08-04
- 状态：已采纳
- 决策：先由家庭事实生成资产负债、现金流、保障、目标资金和流动性五张底表，再运行 20 个单独指标函数；GET 分析保持无副作用，只有 POST 运行接口保存快照和审计。
- 原因：先核算再比率可发现重复、漏项和口径矛盾；纯函数和显式规则版本可复现、可解释、可审计，也彻底排除 LLM 心算。
- 影响：每项指标必须返回输入、实际代入、分子／分母、适用性、公式／阈值版本、来源、解释和行动；无有效分母时使用 NULL。用户原文“介于比率”按上下文解释为“结余比率”，即年度税后结余除以年度税后总收入。

## ADR-012：Demo 阈值、保障和购买力口径必须显式降格

- 日期：2026-08-04
- 状态：已采纳
- 决策：无法可靠归为监管或行业标准的区间统一标记 `internal_demo`；保障缺口按四个独立风险场景计算最大单项缺口；CPI、家庭加权通胀、目标成本增速和最低工资追赶分开输出。
- 原因：家庭财务健康不存在可不加条件套用的统一监管阈值，跨保障场景相加会重复计算，最低工资也不能替代 CPI 或投资回报假设。
- 影响：客户端显示参考来源类型与非监管说明，不输出具体保险产品；最低工资追赶参数始终携带 `is_cpi=false` 和 `is_return_guarantee=false`。

## ADR-013：四账户采用资源守恒的顺序瀑布

- 日期：2026-08-04
- 状态：已采纳
- 决策：目标与四账户引擎按高息债务、日常资金、应急储备、必要保障成本、一年内确定支出、一至五年刚性目标、剩余长期资金七步运行，不接受固定四象限比例。
- 原因：家庭责任、目标日期和资金来源因人而异，固定比例会隐藏安全缺口并把短期资金错配给长期风险资产。
- 影响：一年内确定现金流一旦承诺就从后续资源扣除；应急金和目标准备金反事实只重分类现有资产；五项硬约束不得被行为意愿覆盖。70% 的分母只是“扣除优先债务后的可规划资源”；保本的钱 5%—30% 由投研规则按偏积极／中性／偏防守发布三档战术锚，且只调整完成前置安排后的长期资源。两者都不是家庭总资产统一配置。

## ADR-014：组合采用确定性网格、显式降级与三道闸门

- 日期：2026-08-04
- 状态：已采纳
- 决策：组合本金只取动态四账户确认的长期金额；用版本化 5% 网格同时约束尾部损失、目标缺口、回撤、流动性、换手、购买力、成功率与分散度，固定输出稳健／基准／进取三候选。无可行解时使用可审计规则降级。家庭安全、客户审慎下限和产品逐项匹配依次检查，任一上游闸门都不能被市场情景或主动请求覆盖。
- 原因：普通家庭组合建议必须先满足生存与近期责任，并能在无 CVXPY、无模型和无网络时复现；只给单一“最优解”或静默求解失败会隐藏不确定性与适当性冲突。
- 影响：保存优化器版本、固定种子、参数、哈希、状态和降级原因；固定五情景概率明确不是 Monte Carlo 或收益承诺。普通路径优先宽基／多资产，拒绝个股集中、杠杆和股指期货；产品目录逐项披露保证与非保证边界。

## ADR-015：数字孪生采用逐月状态、共同随机数与可取消分阶段运行

- 日期：2026-08-04
- 状态：已采纳
- 决策：家庭孪生从事实层建立逐月年龄、收入、支出、资产、债务、保障、养老金、目标和家庭事件状态；Monte Carlo 保存 seed、路径数、期限、收益／波动／相关性和场景版本。基线、原方案压力和优化方案复用共同随机数。运行按基线、单场景、组合压力、优化结果分阶段持久化，可读取进度、取消和导出。
- 原因：只显示单根预测曲线会掩盖不确定性，重新抽样会把方案差异与随机误差混在一起；不可见长请求难以取消或审计。普通退休提款也不应被错误计作紧急出售。
- 影响：界面使用 P10—P90 分位数扇形、失败时间和尾部路径，并提供精确数据表。被迫出售只统计退休目标之外为弥补现金缺口而变现长期资产；每阶段提交前重新读取取消标记，晚到计算不能覆盖已取消状态。LLM 不参与随机路径或金额计算；所有 Demo 假设标记 `internal_demo`。

## ADR-016：行为画像采用审慎最低值、证据链与可退出实验

- 日期：2026-08-04
- 状态：已采纳
- 决策：七维问卷和六项实验由版本化确定性规则评分，十一项偏差必须逐项给出证据；最终配置上限取客观能力、问卷和实验的审慎最低值。实验可随时退出，退出不生成新画像或干预。十二类干预只在合成／授权测试数据上产生，冷静期未结束不能标记完成；四组 A/B 仅聚合 eligible 测试会话。
- 原因：自述风险意愿可能与下跌时的真实选择冲突，简单平均会放宽适当性；无证据标签、强制完成和暗中交易会伤害客户自主性与审计可信度。关键风险等级也不能交给 LLM 心算。
- 影响：自述能承受 30% 却在下跌 10% 清仓时，实验上限强制降为低风险；行为永远不能上调客观能力。选择、反应时间、修改次数、一致性、冲突、偏差、干预、冷静期、退出和 A/B 分配均进入可追溯记录；所有指标明确不代表收益或干预因果效果。

## ADR-017：可信 AI 采用受控检索、固定状态机与输出后终检

- 日期：2026-08-04
- 状态：已采纳
- 决策：政策与产品知识只从版本化本地快照检索，先做类别／人群／地区／生效期／隔离过滤，再做关键词、离线向量和元数据混合排序。九个智能体按固定顺序调用白名单工具，每步使用独立 Pydantic Schema、超时、失败回退和审计。最终解释必须逐值匹配数字工具账本、受控政策切片和产品目录版本，再通过确定性合规终检。
- 原因：开放式模型常识、自由智能体路由和只在提示词中写禁令都无法证明数字、政策时效、产品版本或适当性没有被绕过；比赛现场还必须在无密钥、无网络时完整运行。
- 影响：自然语言先生成逐项确认草稿，缺失金额不猜测；过期和提示注入切片被排除；普通家庭高风险建议被阻断并转人工。Mock 是默认 Provider，OpenAI／DeepSeek／本地兼容传输也必须输出 JSON Schema 并接受相同终检。Stage 8 的报告步骤只生成受治理模板摘要，不提前替代 Stage 11 的固定八章规划书。

## ADR-018：正式规划书采用结构化八章快照与只追加重算链

- 日期：2026-08-05
- 状态：已采纳
- 决策：正式报告只接受固定八章 `FormalReportDocument`，关键数字来自确定性账本，政策事实来自受控引用；生成、月度复盘、重大事件和行动状态变化都新增 Rn 快照。HTML 自包含，PDF 使用系统／开源中文字体；报告与合规前审核流关联时不向客户暴露。
- 原因：自由文本报告无法可靠证明章节完整、数值一致、政策时效和版本来源；覆盖式更新会破坏投诉回放，浏览器本地行动状态也无法形成持续服务闭环。仓库分发专有字体或依赖在线字体会破坏授权和离线 Demo。
- 影响：数据库约束家庭内报告序号和行动代码唯一；每份报告保存父快照、SHA-256、审核版本和九类治理版本。客户、顾问和风险端分别以阅读／行动、交付、证据为主，但读取同一快照链。PDF 不是法律签名或收益承诺，重大决定仍须人工复核。
