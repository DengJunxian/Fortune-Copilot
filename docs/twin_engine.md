# 家庭财富数字孪生与压力测试引擎

版本：Stage 6 / 2026-08-04  
规则：`data/rules/twin_simulation_v1.json` 1.0.0  
公式：`wealth-state-transition-v1.0.0`  
引擎：`wealth-twin-monte-carlo-v1.0.0`  
结果：`wealth-twin-result-v1.0.0`

## 1. 作用与边界

引擎把已授权的家庭事实转换为逐月状态，生成无冲击基线、原方案压力、优化方案压力和每个单场景的 Monte Carlo 路径分布。大语言模型不进入状态转移、随机数、金额、概率、配置或压力传导。

当前收益、波动、相关性、通胀、收入增长和压力参数全部标记为 `internal_demo`。结果回答“在这一模型和参数下会怎样”，不是收益预测、保本承诺、监管评级或穷尽式风险边界。系统无外部模型、真实银行接口、PostgreSQL或网络时仍可用 SQLite、合成家庭和 Mock 模式完整运行。

以下边界不可被参数覆盖：

- 信用卡可用额度不进入资产、净资产或流动性；信用卡未付进入负债；
- 自住房进入净资产，但不会自动作为目标支出的流动资金；投资房和自住房分别建模；
- 医疗保障只按分析日有效保额减免赔额做简化抵扣，保额本身不进入资产；
- 银行理财、基金、信托、保险等不因名称被统一视为保本；
- 权益比例调整只作用于可投资金融资产，不解释为家庭总资产统一配置；
- 普通家庭没有个股、杠杆或股指期货默认路径；
- 最低工资不参与通胀冲击，也不替代 CPI。

## 2. 输入状态与口径

`build_twin_model_input` 从不可变家庭事实生成以下状态，不读取 `data/expected`：

| 状态 | 来源与口径 |
| --- | --- |
| 成员与年龄 | 出生日期相对分析日；保留已记录退休年龄 |
| 收入流 | 年化后转月；记录类型、成员、波动、退休年龄；劳动收入按金额排序识别主／次收入 |
| 生活支出 | 排除 `debt_service`，避免与负债月供重复扣减；另算必要支出和可压缩支出 |
| 债务 | 本金、年利率、月供、固定／浮动；信用卡未付作为负债 |
| 目标 | 分析日至目标日的月份、今日目标额、已准备额、成本增长率和可延期性 |
| 资产桶 | 现金等价、固定收益、分散权益、实物资产、黄金、养老金、自住房、投资房、其他资产 |
| 保障 | 分析日有效医疗险和重疾险的保额、免赔额 |
| 养老金 | 社保、公积金、年金的个人与单位年度缴费之和转月 |

初始净资产恒等式为：

`初始净资产 = 全部资产桶之和 − 全部未偿债务`

社会保障账户余额如果已经作为资产事实存在，不会因缴费账户再次重复加入起点资产。目标的 `prepared_amount` 是目标证据，不会在起点再次加到资产。

请求保存分析日、seed、路径数、期限、输出间隔、场景代码、场景覆盖、计划调整、基础假设覆盖和家庭事件。金额字段使用十进制字符串；路径为 100—5000，期限为 5—60 年，最多组合 6 个场景。

## 3. 随机数与相关结构

每条路径使用独立但可复现的随机流：

`path_seed = seed XOR ((path_id + 1) × 2,654,435,761)`

五类可投资资产按规则相关矩阵进行 Cholesky 分解。规则加载时校验矩阵维度、对称性、对角线和正定性；用户覆盖矩阵也必须通过同样校验。月收益使用截断的相关高斯冲击：

`r_month = exp((ln(1 + μ) − 0.5σ²) / 12 + σ / √12 × clip(z, −8, 8)) − 1`

单月结果再限制在 `[-95%, 150%]`，防止极端输入产生非有限值。首月市场压力以乘法方式合成：

`r_after_shock = (1 + r_month) × (1 + shock) − 1`

无冲击基线、原方案压力和优化方案使用相同 seed、path_id 和随机生成顺序，即共同随机数。方案差异来自显式场景或计划参数，不来自重新抽样。

## 4. 逐月状态转移

每个月严格按以下顺序执行：

1. 更新现金等价、固定收益、分散权益、实物资产和黄金收益；首月叠加一次性冲击；
2. 更新自住房／投资房估值、养老金收益和其他资产折旧；
3. 按收入增长与收入波动生成当月收入；到退休年龄后劳动收入归零，失业和收入下降压力随后作用；投资房空置只停止租金；
4. 收入与显式新增月储蓄进入现金；仍有劳动收入时加入养老金缴费；
5. 生活支出按通胀增长，叠加赡养、医疗和自定义家庭事件；
6. 负债按 `利息 = 上月本金 × 当月年利率 / 12`、`计划偿还 = min(本金 + 利息, 月供)` 摊还；浮动房贷叠加利率冲击；
7. 目标只在到期月扣减一次；教育超支在同月加入，目标提前按新到期月重算成本增长；
8. 记录资产、负债、未履行义务、净资产、流动资产和长期资产快照。

支出顺序为现金等价 → 固定收益 → 黄金 → 实物资产 → 分散权益；只有退休或全部劳动收入已退休时才允许动用养老金。无法支付的生活／债务支出形成未履行义务并进入负债；目标未支付部分形成目标短缺。

“被迫出售”定义为退休目标之外，为弥补生活、债务或其他目标现金缺口而卖出黄金、实物资产、分散权益或养老金。全部劳动收入退休后的正常长期资产提取、以及退休目标的计划性提取不计为被迫出售。这一口径防止把正常退休提款机械地算成 100% 紧急出售。

家庭事件中的一次性支出、月支出增加和月收入损失各扣减一次。收入中断测试同时验证中断期主收入实际支付最大值为 0；目标测试验证每个目标在每条路径只发生一次扣减。

内部状态使用浮点随机过程，但所有支付判断采用 0.005 元半分容差：小于半分的生活、债务或目标尾差归零，避免不同 Python／数学库环境把 `10⁻¹⁰` 元级舍入残差误判为资金耗尽或目标失败；API 金额最终仍按 Decimal 分位舍入到分。

## 5. 压力场景及组合规则

当前目录共 19 个、版本 1.0.0，全部可组合：

| 类别 | 场景代码 | 默认冲击 |
| --- | --- | --- |
| 收入 | `primary_income_interruption_6m` | 主劳动收入中断 6 个月 |
| 收入 | `one_income_reduction_30` | 次劳动收入 24 个月下降 30% |
| 保障 | `medical_out_of_pocket` | 首月医疗自付冲击 200,000 元，先抵扣有效保障 |
| 家庭 | `dependent_support_increase` | 赡养支出每月增加 3,000 元，持续 120 月 |
| 目标 | `education_overrun` | 教育目标到期额外增加 200,000 元 |
| 生命周期 | `early_retirement` | 劳动收入停止年龄提前 5 年 |
| 生命周期 | `longevity` | 退休后支出期限延长 10 年，不增加工资期限 |
| 债务 | `mortgage_rate_up` | 浮动房贷年利率增加 1.5 个百分点 |
| 房产 | `investment_property_vacancy_discount` | 投资房租金中断 12 月且估值折价 20%；无投资房则不适用 |
| 市场 | `equity_down_20` / `30` / `40` | 分散权益首月下跌 20%／30%／40% |
| 市场 | `bond_rate_shock` | 固定收益首月下跌 10% |
| 市场 | `gold_reit_volatility` | 黄金、实物资产首月下跌 15%，波动放大 1.75 倍 |
| 市场 | `multi_asset_drawdown` | 固收、权益、实物、黄金同步负向冲击 |
| 市场 | `prolonged_low_return` | 除现金外长期年化收益减少 3 个百分点 |
| 通胀 | `cost_inflation_up` | 生活与目标成本年增速增加 2 个百分点 |
| 目标 | `goal_advanced` | 全部未完成目标提前 24 个月 |
| 组合 | `unemployment_equity_down_30` | 主收入中断 6 个月 + 权益首月下跌 30% |

组合时，金额型冲击求和，持续期和提前／延后年限取最大，收益冲击用乘法合成，波动倍数取最大，长期收益降幅取最大，通胀增量求和后设上限。用户显式覆盖值优先，并进入参数哈希。正向覆盖可能使压力结果高于基线，此时结果必须携带解释，不能仍声称“压力不会更好”。

## 6. 输出定义

每个分布保存：

- 净资产 P10／P25／P50／P75／P90 扇形序列，以及中位流动资产、长期资产和负债；
- 全目标同时成功概率、逐目标成功／失败概率、到期金额与短缺中位数；
- 首次目标失败年份分布和最常见失败目标；
- 资金耗尽概率、被迫出售概率与出售金额中位数；
- 按期末净资产、目标短缺和路径编号排序的最差 5 条固定 seed 样本；
- 数值有限、失业期收入、目标扣减次数和共同随机数校验。

`目标成功概率 = 所有目标均按期足额支付的路径数 ÷ 总路径数`

`资金耗尽概率 = 曾出现生活／债务支出无法足额支付的路径数 ÷ 总路径数`

`被迫出售概率 = 被迫出售长期资产金额 > 0.01 元的路径数 ÷ 总路径数`

每个单场景还统一回答：应急资金可撑月数、最先失败目标、被迫出售、保障抵扣和剩余医疗缺口、退休是否需延后及年数、可压缩月支出、所需新增月储蓄、目标成功概率变化。投资房场景对无投资房家庭返回 `applicable=false`，不会把自住房当投资房。

## 7. 原方案与优化方案

原方案压力保留家庭现有计划；优化方案只应用请求中明确提交的退休年龄、新增月储蓄、权益比例和流动性重分类。流动性重分类从分散权益、实物资产、黄金和固定收益依次转入现金，不改变起点总资产或净资产。

比较结果同时保存基线、原压力、优化压力的目标成功概率和被迫出售概率，以及压力相对基线、优化相对原方案、避免被迫出售概率的实际差值。界面只有在差值为正时才表述“减少”；未改善时明确显示没有改善。

## 8. 持久化任务、取消与 API

运行不是不可见的长请求。POST 创建 `queued` 运行，客户端显式推进可恢复阶段：

`queued → baseline 20% → 单场景 20%—55% → 原组合压力 70% → 优化方案与结果 100%`

每个阶段把部分结果写入 `SimulationRun.outputs`。取消操作写 `simulation_cancelled` 审计事件；昂贵阶段在落库前重新读取取消标记，防止晚到的计算覆盖已取消状态。完成后写 `simulation_executed` 审计事件和完整结果。只有完成运行可以导出。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/v1/twin/scenarios` | 读取 19 个版本化场景 |
| POST | `/api/v1/households/{id}/twin/runs` | 校验输入并创建运行 |
| POST | `/api/v1/households/{id}/twin/runs/{run_id}/advance` | 推进一个可恢复阶段 |
| GET | `/api/v1/households/{id}/twin/runs/{run_id}` | 读取进度、状态或完整结果 |
| POST | `/api/v1/households/{id}/twin/runs/{run_id}/cancel` | 取消并写审计证据 |
| GET | `/api/v1/households/{id}/twin/runs/{run_id}/export` | 导出已完成 JSON |

`SimulationRun` 保存 seed、路径数、期限、步长、场景代码、输入／公式／结果／引擎／规则版本、参数哈希、计算来源、阶段、进度、取消标记、起止时间和错误码。`ScenarioDefinition` 保存场景版本、是否可组合、来源类型与启用状态。

## 9. 主 Demo B 标准答案

独立夹具为 `data/expected/demo_b_twin_v1.json`，运行时不读取。固定输入：分析日 2026-08-04、seed 20260804、100 路径、30 年、失业 6 个月 + 权益下跌 30%；优化方案将退休年龄设为 62 岁，每月新增储蓄 2,000 元、权益假设 30%，把 120,000 元长期资产重分类为流动性。

| 结果 | 无冲击基线 | 原方案压力 | 优化方案压力 |
| --- | ---: | ---: | ---: |
| 全目标成功概率 | 0.960000 | 0.530000 | 1.000000 |
| 资金耗尽概率 | 0.290000 | 0.390000 | 0.000000 |
| 被迫出售概率 | 1.000000 | 1.000000 | 0.040000 |
| 被迫出售金额中位数 | 27,143.23 | 126,714.68 | 0.00 |
| 期末净资产 P10 | 1,761,600.39 | 1,480,352.75 | 3,583,448.43 |
| 期末净资产中位数 | 5,613,217.18 | 5,130,539.91 | 7,417,985.04 |

十年教育目标使原方案组合压力下的全目标成功概率从无冲击基线 0.960000 降至 0.530000；显式优化方案在这 100 条固定路径中为 1.000000。优化同时把资金耗尽概率从 0.390000 降至 0.000000、被迫出售概率减少 0.960000。该结果只证明固定 Demo 输入下流动性和储蓄反事实的作用，不是对任何真实家庭的建议。

## 10. 测试与已知限制

自动测试覆盖固定 seed 字节级复现、19 场景目录与数据库种子、失业期主收入归零、目标一次性扣减、60 年极端参数无 NaN／无溢出、压力结果不优于基线（除非显式正向覆盖）、B 标准答案、分阶段推进、导出、完成／取消审计和前端取消交互。

已知限制：

- 收益分布使用对数正态近似和固定相关矩阵，不拟合历史厚尾、波动聚类或状态切换；
- 税收、交易成本、保险合同责任、养老金领取规则、房产交易摩擦和继承未做完整法律／精算建模；
- “所需新增月储蓄”是目标短缺中位数除以模拟月份的简化敏感性，不是重新求解的最优储蓄计划；
- 被迫出售区分紧急变现与退休计划提取，但不追踪每项资产的税基和交易损失；
- 最差 5 条是固定样本中的尾部路径，不是理论最坏边界；
- 100 路径用于快速 Demo；重要决策应提高路径数、复核参数来源并进行人工审阅。
