# 理念对齐与合规校准说明

本项目必须完整体现用户提出的原创方向：不照搬标准普尔家庭资产象限图，而是面向中国家庭的收入结构、住房负担、赡养育儿、社会保障、个人养老金、消费习惯、风险认知和行为偏差，构建“华衡·中国家庭财富管理框架”。

## 一、四账户原始思想与正式产品定义

### 1. 要花的钱：日用支付与短期流动账户

用户原始思想：
- 不按总资产固定配置 10%；
- 只保留满足衣食住行、信用卡还款和近期消费的少量资金；
- 一般可能只需数千元，但应因人而异；
- 主要工具包括信用卡和货币基金。

正式产品规则：
- 信用卡是支付工具和短期负债管理工具，不是家庭资产，也不是应急储备；
- 信用卡可用额度只可作为“备用授信信息”展示，不计入资产、净资产或流动性覆盖；
- 日用账户的真实资金来源包括现金、活期存款、可即时赎回且风险较低的货币市场工具；
- 目标金额由未来 30—90 天确定性支出、账单周期、收入发放周期和小额意外支出计算，不按总资产固定比例；
- 数千元只能作为某些样例家庭的结果，不能作为全体家庭统一规则；
- 另行计算 3—12 个月应急储备。应急储备可以与日用账户在界面中相邻，但必须区分“日常周转”和“收入中断缓冲”。

### 2. 保命的钱：风险保障账户

用户原始思想：
- 核心是意外、医疗、重疾、车险等风险保障；
- 强调“保险只消费，不投资”；
- 希望以较低保费获得覆盖全家的基础保障；
- 个人养老金中偏稳健部分可以进入稳健账户。

正式产品规则：
- 风险保障账户只统计为转移重大风险而支付的保障性保费、保额、免赔额、等待期和责任范围；
- 定期寿险、医疗险、重疾险、意外险、车险等按保障责任分类；
- 不能用“每年几千元一定管全家”作为算法或宣传承诺，保费和保额必须由家庭责任、健康情况、年龄、收入、社保、免赔额和保障缺口决定；
- “保险只消费，不投资”在产品中落实为“保障优先、保障与储蓄分账”：纯保障部分进入保命账户；分红险、年金险、万能险等兼具储蓄功能的产品，必须拆分展示保障责任、保证利益、非保证利益、现金价值、退保损失和流动性约束，不能简单按理财产品处理；
- 不得重复计算同一保险产品的保费、现金价值和保额；
- 个人养老金属于专用长期养老制度，不属于保险账户本身。其产品按底层风险、锁定期限和目标用途归入稳钱或生钱账户，但必须保留“个人养老金专户”标签。

### 3. 保本的钱：正式命名为“稳钱的钱／稳健目标账户”

用户原始思想：
- 主要用于保值、流动性和未来较大开支；
- 包括存款、银行理财、养老金、教育金、债券、信托、分红险等；
- 希望占比约为 5%—30%，并随市场环境变化；
- 行情好时减少，行情差时增加。

正式产品规则：
- 对用户界面可保留“保本的钱”作为认知入口，但正式产品名称、报告标题、接口字段和合规文案统一使用“稳钱的钱／稳健目标账户”；
- “保本”只表示家庭对目标本金安全的偏好，不代表任何理财、基金、信托、债券或保险产品得到本金保证；
- 定期存款、银行理财必须分开建模；银行理财不得被归类为存款；
- 稳钱账户用于未来 1—5 年的刚性目标、较大支出、债务缓冲和低波动资金，不只看收益率，还看期限匹配、提前赎回、净值波动、信用风险和流动性；
- 5%—30%只能作为满足条件后的“可投资金融资产”或“年度新增可配置结余”的参考带，不能作为家庭总资产的统一标准；
- 市场状态只能触发有边界的战术调整，不能简单按“行情好就买更多风险资产、行情差就卖出风险资产”。必须设置调整上限、冷静期、换手成本、再平衡阈值和行为偏差拦截；
- 信托、分红险等复杂或长期锁定产品必须通过适当性、流动性、信息披露和家庭目标匹配后才能进入候选池。

### 4. 生钱的钱：长期增长账户

用户原始思想：
- 主要使用指数基金等长期投资工具；
- 普通家庭原则上不鼓励直接炒股；
- 可以研究期指等工具，但必须考虑行为金融风险；
- 房产投资在当前中国家庭配置中不应被默认推荐；
- 希望在条件允许时将 70% 以上资金投入长期增长；
- 长期目标至少跑赢通胀，并以最低工资增长作为中国本土购买力信号。

正式产品规则：
- 长期增长账户只接收完成高息债务处理、日用流动、应急储备、保障缺口和中短期刚性目标锁定后的剩余长期资金；
- 70%以上只能指“通过所有安全闸门后的长期可投资金融资产”或“年度新增长期结余”，并且仅适用于期限长、收入稳定、风险能力充足、无重大近期开支、保障充分的家庭；
- 默认以低成本、分散化的宽基指数基金和多资产组合为核心，不默认推荐个股、主题追逐、杠杆、场外配资或集中持仓；
- 股指期货和其他衍生品不进入普通家庭的默认推荐结果。仅可作为专业投资者、明确套期保值需求和严格适当性条件下的研究或教育沙箱，并设置资金门槛、知识测试、交易经验、最大损失和人工复核；
- 自住住房作为家庭核心使用资产和高集中度非流动资产单独建模；投资性房产不作为默认增配方向，系统通过租金、空置、税费、维护、折价变现和价格下行情景进行客观评估，不做无法验证的长期市场断言；
- “必须保本且跑赢通胀”改写为：长期增长账户追求在可承受风险范围内提高长期实际购买力，但不承诺本金不亏损或一定跑赢任何基准；
- 最低工资增速保留为“中国民生收入追赶基准”，用于长期回溯评价和压力测试，不直接等同 CPI。系统同时使用官方 CPI、家庭个性化消费价格指数、教育／医疗／养老等目标专项成本指数。

## 二、比例的统一口径

系统中每个百分比必须明确分母：
1. 家庭总资产；
2. 可投资金融资产；
3. 流动金融资产；
4. 年度税后收入；
5. 年度新增结余；
6. 通过安全闸门后的长期可投资资金。

禁止只显示“日用 5%、稳钱 20%、生钱 75%”而不标明分母、计算时间和适用条件。

## 三、规划书固定八章结构

最终面向客户的正式规划书必须保持以下一级目录：
1. 家庭基础情况；
2. 理财目标；
3. 大额支出计划；
4. 理财假设；
5. 家庭财务报表；
6. 家庭财务比率分析；
7. 投资规划建议；
8. 免责声明。

压力测试、行为金融、个人养老金、保险、债务、四账户、智能投顾、行动日历等内容放在第 7 章的二级目录或报告附录中，不改变上述八章主结构。

## 四、AI 与金融的职责边界

- 大语言模型：负责自然语言录入、信息抽取、缺失项追问、通俗解释、报告叙述和对话；
- 确定性计算引擎：负责财务报表、比率、现金流、未来值、保障缺口、目标缺口和数值校验；
- 优化与仿真引擎：负责四账户分配、组合候选、Monte Carlo、压力测试和反事实分析；
- RAG 与知识图谱：负责政策、产品条款、适当性规则和来源追踪；
- 行为金融引擎：负责识别追涨杀跌、损失厌恶、过度自信、从众、处置效应等偏差并实施干预；
- 人工：负责高风险产品、复杂产品、不匹配购买、重大权益影响和异常建议复核。

任何 LLM 输出不得覆盖确定性计算、适当性拦截和人工复核要求。

```text

项目名称：智衡财富·WealthTwin
正式定位：面向中国家庭的财富数字孪生与智能投顾操作系统
理论体系：华衡·中国家庭财富管理框架
核心价值主张：智衡财富不是替用户预测市场，而是帮助中国家庭在不确定的市场中，仍然能够完成确定的人生目标。
宣传表达：不是把一张国外比例图搬进中国，而是为每个中国家庭生成一条能够计算、解释、执行和检验的财富路径。

一、先做仓库审计
1. 阅读所有已有 README、架构文档、代码、测试、环境配置和数据库迁移。
2. 输出当前仓库能力清单、缺口清单、风险清单和增量实施顺序。
3. 保留已有可用代码、接口和界面；没有充分理由不得推倒重写。
4. 若仓库为空，按下述推荐架构建立 monorepo；若已有技术栈，则在不牺牲核心目标的前提下适配现有结构。
5. 审计完成后立即开始实现，不要停留在建议层面，不要要求用户重复确认报告中已经明确的需求。

二、统一产品理论框架
系统必须完整实现并在产品中可见：
1. 一核：家庭人生目标、家庭韧性与长期生活质量。
2. 四账：
   - 要花的钱／日用支付与短期流动账户；
   - 保命的钱／风险保障账户；
   - 稳钱的钱／稳健目标账户。对用户可解释为原始理念中的“保本的钱”，但绝不承诺保本保收益；
   - 生钱的钱／长期增长账户。
3. 四账户不是固定比例图，而是依次通过约束的资金瀑布：
   - 日用与账单周转；
   - 应急缓冲与高息债务处理；
   - 基础保障缺口；
   - 未来 1—5 年刚性目标；
   - 剩余长期资金增长。
4. 五项硬约束：流动性、偿债能力、保障缺口、目标期限、风险适当性。
5. 一项行为修正约束：行为承受力。整体对外可表述为“五硬一软”或“六约束”。
6. 三尺／三种核心配置分母：家庭总资产、可投资金融资产、年度新增结余；同时支持流动金融资产和长期可投资资金口径。任何比例必须明确分母。
7. 双画像：家庭财务画像、行为金融画像。
8. 四维风险评估：风险能力、风险意愿、产品理解能力、实际风险行为；发生冲突时采用更审慎的上限。
9. 六阶段生命周期：初入职场、婚姻组建、育儿成长、家庭成熟、退休准备、养老传承。
10. 四重购买力评价：
    - 官方 CPI；
    - 个性化家庭消费价格指数；
    - 教育、医疗、养老、住房等目标专项成本指数；
    - 地区最低工资增速形成的“民生收入追赶基准”。
    最低工资不得直接等同通胀，只能作为中国本土生活与收入底线的辅助长期指标。
11. 北极星指标：家庭核心目标按期实现概率；辅以极端情景生存能力、长期执行率、流动性安全、风险理解度和合规拦截率。不得以预测收益率作为唯一目标。
12. 对“70%以上进入生钱账户”的实现：只有在家庭通过全部安全闸门后，才允许长期增长账户占长期可投资资金或年度新增长期结余的 70% 以上；不得按家庭总资产直接套用。
13. 对“稳钱账户 5%—30%”的实现：将其作为可投资金融资产或年度新增结余的动态参考带，并由目标期限、流动性、家庭风险能力、市场估值和行为偏差共同决定。
14. 对“行情好／行情差动态调整”的实现：市场状态只能做有边界的战术调整，战略配置始终由家庭目标决定。设置单次调整上限、冷静期、最小持有期、换手成本和再平衡阈值，防止模型追涨杀跌。

三、项目明确不是什么
产品不得被实现为：
- 简单记账软件；
- 固定 10%/20%/30%/40% 比例分配工具；
- 基金或理财产品销售货架；
- 让大语言模型直接心算配置比例的 AI 理财问答；
- 预测股市涨跌的量化交易系统；
- 承诺保本、保收益或“稳赚不赔”的工具；
- 面向普通用户默认推荐个股、杠杆或股指期货的系统。

四、核心用户与场景
至少支持：
- 大学生与初入职场者；
- 年轻家庭；
- 城市中产；
- 灵活就业者；
- 临退休家庭；
- 后续可扩展的高净值家庭。
比赛 MVP 主客群为有房贷、育儿、养老和赡养责任的中国城市家庭。

五、三端协同产品
1. 客户端：家庭财富驾驶舱。
2. 顾问端：工行客户经理／理财经理智能工作台。
3. 风险端：适当性、消费者保护与审计控制台。
三端必须共享同一套家庭数据、计算结果、方案版本和审计链，按角色隔离权限。

六、完整业务流程
隐私授权与家庭建档

十二、动态四账户算法
实现“先约束、后优化”的顺序：
税后收入、现有流动资产和可配置金融资产
→ 识别信用卡未付与高息消费债务
→ 计算未来 30—90 天日常支付和账单周转
→ 计算 3—12 个月应急储备
→ 计算基础保障缺口与可负担保费
→ 锁定未来 1—5 年刚性目标资金和债务缓冲
→ 确定稳钱账户参考带
→ 将剩余长期资金进入生钱账户优化
→ Monte Carlo 与压力测试
→ 行为偏差检查
→ 适当性审查
→ 生成可执行行动清单。

1. 要花的钱
- 由必要月支出、收入发放周期、信用卡账单日／还款日、未来 90 天确定性支出计算；
- 默认不按总资产比例；
- 信用卡额度不计入资产，信用卡未付计入负债；
- 输出“支付工具”和“背后真实资金”两层视图。

2. 应急储备
- 与日常支付资金分开计算；
- 收入稳定、双收入家庭可使用较低月数；单收入、灵活就业、重病风险或高固定支出家庭使用较高月数；
- 参数全部可配置，界面必须解释原因。

3. 保命的钱
- 使用保障缺口法，而不是固定 10%；
- 对家庭经济支柱计算身故／失能责任缺口；
- 对医疗、重疾、意外、车险等分别建模；
- 保障性保费与储蓄性现金价值分账；
- “几千元管全家”只能作为特定家庭样例，不得成为默认承诺。

4. 稳钱的钱
- 匹配未来 1—5 年重要目标、较大开支和债务缓冲；
- 产品池可包括存款、国债、符合条件的低波动固定收益类产品、短久期债券工具、个人养老金中的稳健产品等；
- 银行理财单独建模，不得作为存款或法定保本产品；
- 参考比例 5%—30%，分母默认为可投资金融资产或年度新增结余；
- 根据目标期限和安全垫决定战略权重，根据市场状态仅做有限战术偏移；
- 战术偏移单次不超过可配置上限，默认建议不超过 5—10 个百分点，并设置冷静期与最小持有期。

5. 生钱的钱
- 只使用五年以上且不影响家庭基本生活和刚性目标的长期资金；
- 默认以宽基指数基金、多资产基金或透明、低成本、分散化工具为核心；
- 个股、主题基金、杠杆、衍生品和投资性房产不作为普通家庭默认推荐；
- 当家庭满足长期期限、保障充分、收入稳定、流动性充足、风险能力较高、行为承受力合格等条件时，可允许该账户占长期可投资资金或年度新增长期结余的 70% 以上；
- 所有增长方案必须展示可能亏损、最大回撤、恢复时间和目标失败概率。

6. 动态调整
动态权重不得由大语言模型直接决定。建立规则与优化器：
- 家庭约束和目标期限为主；
- 市场估值、波动和流动性状态为辅；
- 行为偏差作为减速器；
- 交易成本和税费作为约束；
- 采用阈值再平衡与定期复核，不做无边界择时。

十三、目标规划与组合优化
1. 每个目标包含：名称、目标金额、时间、刚性、可延期性、最低可接受金额、已准备资金、优先级、专项成本增长率。
2. 支持目标现值、未来值、月度／年度所需投入、准备率和成功概率。
3. 资金不足时必须识别目标冲突，输出调整选项：延长时间、降低金额、提高储蓄、降低其他目标优先级、调整风险预算；不得生成不可执行的完美方案。
4. 投顾分三层：资产类别建议、产品类型建议、具体产品匹配。比赛版重点完成前两层，第三层只使用模拟产品库。
5. 目标函数至少体现：CVaR、目标缺口、最大回撤、流动性缺口、换手成本；同时提高目标成功概率、长期实际购买力和分散度。
6. 约束：客户风险等级、产品风险等级、目标期限、最低流动性、最大资产集中度、最大回撤、单类资产上限、单产品上限、最低起购额、交易成本和适当性规则。
7. 输出稳健、基准、进取三个候选方案，显示目标成功率、预期区间、极端损失、流动性影响、适用条件和推荐理由。
8. 市场状态只能做有限战术调整；战略配置由家庭目标决定。实现“阈值 + 日历”再平衡：绝对偏离 5 个百分点、相对偏离 20% 或每半年复核可触发，参数可配置。
9. 长期购买力评价至少同时比较：官方 CPI、家庭个性化消费价格指数、目标专项成本指数、地区最低工资滚动增速。最低工资增速只作为“民生收入追赶基准”，不得替代通胀。
10. 普通家庭默认不推荐股指期货。系统若保留期指能力，只能放在专业投资者教育／套保沙箱中，并要求适当性准入、知识测试、交易经验、明确套保头寸、损失上限、保证金压力测试和人工复核。
11. 任何组合都不得表达“必须保本且跑赢通胀”。正确表述为“在可承受风险和目标期限内，提高长期实际购买力与目标成功概率”。
12. 投资性房产不作为默认推荐资产。系统必须计算房产集中度、租售比、空置、税费、维护和折价变现情景，再决定是否保留、减持或不新增。
```

# 提示词 3：确定性金融计算引擎与财务体检

```text
本阶段必须严格对齐用户提出的家庭财务报表与比率分析流程。先生成家庭基础情况、资产负债表、现金流量表、保险保障表、目标资金表和流动性矩阵，再计算比率。不得让大语言模型心算任何指标。

资产分类必须把“定期存款”和“银行理财”分开；信用卡额度不是资产，信用卡未付是负债；自住住房和投资性房产分开；保险保额、保费和现金价值不得重复计入。
实现可审计、可复用的确定性金融计算引擎。大语言模型不得参与计算。

一、财务报表
生成：
- 家庭资产负债表；
- 家庭现金流量表；
- 保险保障表；
- 目标资金表；
- 资产流动性矩阵。
检查会计恒等式、重复资产、漏记负债、收入支出矛盾、异常收益率和过期估值。

二、指标函数
每个指标单独纯函数，返回：metric_id、name、formula、inputs、result、unit、threshold_version、status、explanation_key、data_as_of、source_type、applicability。

必须显式实现用户要求的六类核心比率：
1. 流动性比率／流动储备月数 = 高流动性资产 ÷ 月必要支出，单位为“月”；
2. 短期偿债覆盖率 = 高流动性资产 ÷ 未来十二个月到期债务及刚性大额支出；
3. 负债比率 = 总负债 ÷ 总资产；
4. 结余比率 = 年度税后结余 ÷ 年度税后总收入。用户原文中的“介于比率”按“结余比率”实现，并在需求文档记录该解释；
5. 财务负担率／偿债负担率 = 年度债务本息支出 ÷ 年度税后总收入；
6. 投资与净资产比率 = 可投资金融资产 ÷ 家庭净资产；
7. 房产与资产比率 = 房产总价值 ÷ 家庭总资产；
8. 住房净权益占净资产比例 =（房产价值－相关房贷余额）÷ 家庭净资产。

同时实现：总资产、总负债、净资产、应急储备月数、12 个月流动覆盖率、固定支出率、投资资产净值比、房产集中度、短债覆盖率、保障覆盖率、保障缺口、养老资金充足率、目标准备率、收入集中度、产品 HHI、财务自由度。

每个指标在前端必须直接展示：
- 中文名称和英文／代码标识；
- 完整公式；
- 本家庭实际代入值；
- 分子、分母和数据日期；
- 当前值；
- 参考区间和适用条件；
- 参考区间来源；
- 风险等级；
- 通俗解释；
- 一项以上可执行改善动作。
不得只显示红黄绿颜色。

三、阈值配置
建立 RuleVersion 和 YAML/JSON 配置。初始 Demo 阈值只作为规划起始参考：
- 稳定收入应急储备 3—6 月、波动收入 6—12 月；
- 短期偿债覆盖率 <1 预警，1—1.5 关注，>1.5 相对充足；
- 总负债率 <30% 较稳健、30%—50% 关注、>50% 重点分析；
- 偿债负担率 <30% 较稳健、30%—40% 关注、>40% 预警；
- 结余率 <10% 偏低、10%—20% 有改善空间、20% 以上具备持续积累能力、30% 以上较好；
- 房产与资产比率 >60% 提示集中，>75% 重点分析流动性；该阈值必须结合城市、是否自住、房贷和家庭生命周期解释；
- 投资与净资产比率不设“一刀切越高越好”规则，按年龄、责任、目标期限和净资产正负状态动态评价；
- 保险覆盖不使用固定保费比例作为唯一标准，必须以保障缺口为主、支付能力为辅。

每条阈值必须有 `source_type`：
- `official_rule`：监管或正式政策；
- `industry_reference`：行业／教材参考；
- `internal_demo`：项目内部 Demo 参数。

无法提供可靠来源的合理区间必须标记 `internal_demo`，界面和报告必须明确说明其不是监管统一标准。

四、保障缺口
实现身故责任、医疗自付、意外和家庭责任等可配置模型。输出最主要不可承受风险、覆盖率、缺口、优先级、保费压力；不直接输出具体保险产品。

五、四重购买力评价
实现：
- 官方 CPI 基准；
- 家庭个性化消费通胀：按家庭支出权重加权；
- 教育、医疗、养老、住房等目标专项成本增长；
- 地区最低工资滚动增速形成的民生收入追赶指数。
最低工资仅作为辅助长期参数，在数据字典和前端中明确标明不是 CPI 替代，也不是收益保证线。

六、API 与页面
提供 `/households/{id}/statements`、`/metrics`、`/diagnostics`。
客户端先完成财务体检概览：资产负债、现金流、健康雷达、指标详情弹层。每个指标显示“是什么、怎么算、为何异常、如何改善”。最后一项先由模板解释，后续接入 LLM。

七、测试
- 为所有指标建立标准答案基准集；
- 主 Demo 精确匹配预期数值；
- 边界：零收入、负净资产、无房产、浮动收入、多套房、缺失数据、Decimal 舍入；
- 关键金融计算正确率必须达到 100%。

验收：
- 主 Demo 财务体检可在前端完整查看；
- 任意数字可点击查看公式和输入；
- 报表可导出 JSON；
- 测试和文档完整。
```

# 提示词 4：目标规划、六阶段生命周期与动态四账户瀑布算法

```text
本阶段必须把用户提出的四账户思想实现为“顺序式资金瀑布”，而不是复刻固定比例象限图。

正式账户名称和含义：
- 要花的钱：日用支付和短期流动，不按总资产固定 10%；信用卡是支付工具，不是资产；
- 保命的钱：保障缺口驱动，强调保障优先和保障／储蓄分账；
- 稳钱的钱：对应用户原始理念中的“保本的钱”，但不得承诺保本保收益；参考带 5%—30%，必须标明分母和适用条件；
- 生钱的钱：长期增长，符合全部安全条件时可以占长期可投资资金或年度新增长期结余的 70% 以上。

市场好坏只能作为有限战术输入。必须防止追涨杀跌和频繁切换。
实现目标驱动的家庭规划和动态四账户系统，禁止固定比例。

一、生命周期
根据成员年龄、婚姻、子女、职业和退休状态识别六阶段：初入职场、婚姻组建、育儿成长、家庭成熟、退休准备、养老传承。允许人工修正。生命周期只影响参数和解释，不可替代个体数据。

二、目标规划
计算每项目标的未来金额、现值、已准备资金、资金缺口、月度／年度投入、优先级、刚性和可延期性。
当目标之间冲突时，输出可执行的调整组合，不得隐藏缺口。

三、四账户算法
实现顺序约束：
1. 高息债务处理；
2. 日常资金；
3. 应急储备；
4. 必要保障成本；
5. 一年内确定支出；
6. 一至五年刚性目标；
7. 剩余长期资金。

日用流动目标额 = 月度必要支出 × 动态安全月数 + 未来 12 个月确定性大额支出 - 同期确定现金流。
安全月数综合双收入、职业稳定度、房贷、子女／赡养、健康风险和收入波动。
风险保障账户按保障缺口与必要保费表达，不以总资产百分比表达。
稳健目标账户 = 五年内目标现值 + 债务缓冲 - 已锁定目标资产。
长期增长账户 = max(0, 可投资资源 - 日用层 - 稳健目标层 - 必要保障成本)。

四、三尺
所有页面和 API 同时提供：
- 占家庭总资产比例；
- 占可投资金融资产比例；
- 占年度新增结余比例。
任何“70%”均必须显示适用条件和分母。

五、五硬一软约束
硬约束：流动性、偿债、保障、期限、适当性；软修正：行为承受力。
系统必须解释哪个约束限制了长期增长账户。

六、反事实解释
实现“改变什么会改变方案”：例如补足应急金、提高教育准备率、减少高息债务、延后目标、提高月储蓄后，重新计算账户区间。

七、页面
实现四账户驾驶舱、目标时间轴、约束解释、金额／比例切换、当前值与建议值对照、缺口、行动优先级和产品类型教育。

八、测试
- 三个家庭必须生成明显不同的四账户结果；
- 两年内购房目标必须提高稳健目标账户；
- 应急金不足时不得把新增资金全部进入增长账户；
- 信用卡额度不得计入流动资产；
- 70% 情景仅在前置条件满足时出现。

验收：
- 客户端可完成目标录入、冲突识别、四账户计算和反事实重算；
- 每个结果可追溯到输入、公式、规则版本；
- 输出行动清单草案。
```

# 提示词 5：组合优化、模拟产品库与适当性三道闸门

```text
本阶段必须实现“长期资金尽量增长，但不以牺牲家庭安全为代价”的核心思想。

普通家庭默认产品方向：
- 宽基指数基金和分散化多资产工具优先；
- 个股和高集中度主题产品默认不推荐；
- 股指期货只允许进入专业投资者教育／套保沙箱，不进入普通家庭自动推荐；
- 投资性房产不作为默认新增建议；
- 银行理财、债券、信托、分红险等必须分别建模风险、期限和流动性，不得使用“保本产品”笼统归类。
实现资产类别层和产品类型层的智能投顾，不做真实个股交易，不伪装工行真实产品接口。

一、模拟产品库
至少包括现金、存款、储蓄国债、货币基金、短债／债券基金、银行理财、宽基指数、红利／价值指数、多资产基金、公募 REITs、黄金、养老储蓄、个人养老金适配产品、商业养老保险等类型。
字段：风险等级、期限、流动性、赎回规则、费用、底层资产、历史波动区间、最低金额、适用账户、保证／非保证说明、数据日期、来源、是否 Mock。
禁止把银行理财、债券基金、信托和分红险统一标记为保本。
普通版不提供期指交易建议；可保留只读“专业对冲实验室”占位并默认关闭。

二、资产配置
实现多目标优化：最小化 CVaR、目标缺口、最大回撤、流动性缺口和换手成本；提高目标成功概率、实际购买力和分散度。
使用 CVXPY 时提供求解失败降级策略：规则型候选组合 + 网格搜索。保存随机种子、参数、求解状态和版本。

三、三个候选方案
输出稳健、基准、进取方案。每个显示：资产类别、比例、金额、目标成功率、模拟区间、极端损失、最大回撤估计、流动性、费用估计、适用条件、主要风险、为何不是其他方案。

四、三道闸门
1. 家庭安全闸门：应急、债务、保障、近期目标未满足时限制高风险配置。
2. 客户适当性闸门：能力、意愿、知识、行为，取审慎上限。
3. 产品适当性闸门：产品风险、期限、流动性、复杂度、最低金额。
不通过时拒绝、降级或只提供投资者教育，并记录审计事件。

五、再平衡
实现战略配置、阈值再平衡和有限战术调整。绝对偏离 5 个百分点、相对偏离 20%、半年例行复核，参数可配置。市场情景不得推翻短期目标约束。

六、API 与页面
实现方案对比、产品类型映射、适当性检查详情、拒绝原因、投资者教育卡片。

七、测试
构建不适配案例：
- 低风险用户要求高杠杆；
- 半年后学费投入高波动资产；
- 临退休用户集中复杂产品；
- 应急不足仍扩大投资；
- 高负债仍加杠杆。
明显违规拦截率 100%。

验收：
- 三方案可在前端比较；
- 所有比例由优化器或降级算法生成；
- 任何推荐可查看适当性链；
- 模拟产品清楚标注 Mock。
```

# 提示词 7：行为金融双画像、实验与干预引擎

```text
将行为金融从报告概念转化为可运行产品功能。

一、问卷画像
建立风险意愿、损失厌恶、投资经验、知识、交易频率、注意力和目标纪律问卷，结果不得覆盖客观风险能力。

二、行为实验
至少实现：
1. 上涨 20% 后是否加仓；
2. 下跌 10% 后如何处理；
3. 下跌 30% 后如何处理；
4. 热门高收益产品与适配低热度产品选择；
5. 盈利资产和亏损资产处置选择；

记录选择、反应时间、修改次数和一致性。

三、偏差识别
输出损失厌恶、过度自信、从众、近期偏差、处置效应、锚定、熟悉性、心理账户、现时偏好、追涨杀跌、频繁交易倾向的分数与证据。

若问卷声称可承受 30% 亏损，但下跌 10% 即清仓，最终风险上限取更保守值，并显示个性化解释。行为评分不能任意提高风险等级，只能维持或下调。

五、干预引擎
实现：
- 24/48 小时冷静期；
- 分批投入；
- 自动／定期投入建议；
- 预先承诺；
- 目标进度替代日收益；
- 金额化回撤；
- 长期概率区间；
- 反事实与下跌前预演；
- 冲动赎回二次确认；
- 热榜弱化；
- 一次性收入分配；
- 自动再平衡提醒。
干预必须根据偏差、目标和场景选择，不可只显示通用文案。

六、A/B 框架
支持普通提示、个性化提示、数字孪生损失模拟、冷静期／目标提醒等实验组。仅使用合成或授权测试数据。

七、页面
实现行为实验页、双画像对照、偏差解释、干预记录和“该行为如何影响配置上限”。

八、测试
- 冲突时下调风险；
- 干预不会承诺收益；
- 冷静期状态可审计；
- 用户可退出实验；
- 无行为数据时明确标记信息不足。

验收：
```

```text
1. 开始写页面前，必须先阅读根目录 `/DESIGN.md`、`docs/design/reference_analysis.md` 和 `docs/design/accessibility.md`。
2. 对现有界面调用或按 `redesign-existing-projects` 执行 Scan → Diagnose → Fix，输出 `docs/design/client_ui_audit.md`，先列出泛化 AI 模板、层级混乱、空状态缺失、数字排版、图表误导、响应式和无障碍问题，再定向修改。
3. 只对比赛介绍页、快速体验入口、规划书封面和叙事型空状态选择性调用 `design-taste-frontend`。不得把它对 Landing Page 的电影化规则直接套入 Dashboard。
4. 根据 `awesome-design-md` 的 IBM／Revolut／Linear 样本复核设计取舍，但最终代码只能引用智衡财富自己的 token 和组件名。
5. 每个页面编码前写一行内部 Design Read：页面类型、用户、任务、信任要求、密度、是否允许动效；该内容写入设计审计文档，不必显示在正式 UI。

四、原创视觉语言
1. 总体气质：可信、克制、温和、数据准确、具有中国家庭生活语境；不是证券交易终端，也不是炫技型 AI 网站。
2. 色彩：低饱和深蓝作为主色，品牌红只用于主行动和关键强调，暖金用于人生目标，橙色用于预警；绿色仅表示已完成／已通过，不表示预计收益或“安全”。所有语义同时使用文字或图标，不只靠颜色。
3. 表面：浅色模式为默认，支持深色高密度工作模式；卡片只在表达层级时使用，避免“白卡片 + 大圆角 + 重阴影”的通用模板。
4. 排版：中文优先使用可靠系统字体栈，离线可用；标题克制，正文可读；金额、比例、日期使用 tabular nums；禁止为了“高级感”牺牲中文清晰度。
5. 圆角与阴影：内部控件 4—8px，主要容器 8—12px；阴影低对比且有明确层级，不在所有组件上铺阴影。
6. 品牌边界：显著标注“竞赛原型，非中国工商银行官方产品”；不使用工行 Logo、官方 App 截图、专有字体或足以造成官方产品混淆的视觉复刻。

五、三端信息架构与密度
1. 客户端：目标和家庭任务优先，使用渐进披露；首屏不堆满指标。核心首屏回答“家底怎样、目标能否完成、现在先做什么”。
2. 顾问端：客户列表、异常、目标冲突、方案版本、待办与沟通记录可快速扫描；支持表格、分栏和抽屉，不追求大面积留白。
3. 风险端：规则命中、证据、数值差异、来源、版本、操作者和处置状态优先；高密度但保持稳定对齐和键盘效率。
4. 三端共享同一设计系统，但使用不同 density preset，不允许复制三套互不一致的组件。
5. 导航根据任务设计，不机械套用固定左侧栏；允许顶部主导航 + 情境侧栏／抽屉，但所有页面必须有当前位置、返回路径和面包屑或等价机制。

六、数据可视化
1. ECharts 统一封装 `ChartFrame`、`ChartLegend`、`ChartInsight`、`ChartDataTable`、`ChartErrorState`。
2. 禁止只用饼图。优先使用瀑布图、堆叠条形图、目标时间轴、区间带、扇形置信区间、压力测试小倍数图、情景对比和可排序表格。
3. 概率、收益和净资产预测必须展示区间和假设；不使用单根向上曲线制造确定性。
4. 每图显示标题、单位、时间范围、数据口径、更新时间、数据来源、文字结论和“查看数据表”。
5. 图表支持金额／比例、元／万元切换；Tooltip 数字格式一致；颜色在常见色觉缺陷下可区分。
6. 用户改变情景滑块时，显示重新计算状态、变更前后差异、受影响目标和规则原因，不只更新动画。

七、动效与交互
1. 动效服务于状态变化和因果解释；默认 150—250ms，使用 transform／opacity。
2. 客户端可有轻量入场和方案切换；顾问端、风险端以即时反馈为主。
3. 核心流程禁止强制 GSAP、滚动劫持、持续视差、磁吸按钮、无限 marquee 和长时间卡片堆叠动画。
4. 完整支持 `prefers-reduced-motion`，动效关闭后信息和操作不受损。
5. 所有可点击元素有 hover、focus-visible、active、disabled、loading 和错误状态；关键操作需明确二次确认或撤销。

八、无障碍、响应式与模式
1. 以 WCAG 2.2 AA 为最低目标：键盘可达、焦点顺序、可见焦点、语义 HTML、标签、错误提示、对比度和读屏名称。

九、完整状态

十、解释
每个建议都有“为什么”：使用哪些家庭数据、哪个约束生效、哪个公式、改变什么会改变结果、风险和假设。

十一、端到端与视觉测试
1. 覆盖主 Demo 从建档到规划书的完整路径，不依赖外部模型。
2. Playwright 覆盖键盘主路径、三种 viewport、金额遮罩、模式切换、图表数据表、断网降级和合规拦截。

5. 检查浏览器控制台无错误、所有按钮有动作、无 `#` 死链、无 Lorem Ipsum、无随机外部图片和无未经标注的 Mock。
```

# 附录 E：政策与事实基线

以下内容只能作为当前政策基线，必须在系统中版本化，禁止硬编码为永久事实：

1. 个人养老金
- 当前年度缴费上限按 12000 元的政策参数初始化；
- 允许产品范围按现行政策配置，包括符合规定的储蓄存款、理财产品、商业养老保险、公募基金，以及全面实施后扩展的国债、特定养老储蓄、指数基金等；
- 资金封闭运行、领取条件、税收政策和产品目录均需通过 RAG 更新；
- 系统只做资格与税收影响模拟，不代替税务或养老政策咨询。

2. 资产管理产品
- 银行理财、信托、基金等资管产品不得被宣传为统一“保本保收益”；
- 产品按净值、风险等级、期限、底层资产和流动性建模。

3. 最低工资
- 最低工资是劳动报酬法定底线和基本生活保障制度；
- 在本项目中只作为地区民生收入追赶的辅助信号；
- 不得直接替代 CPI 或作为收益保证线。

4. 适当性
- 银行、理财、信托和保险等产品适当性按照现行金融监管规则建模；
- 证券、基金、期货和衍生品按照证券期货投资者适当性规则建模；
- 普通投资者、高风险产品、不匹配购买和重大风险必须有差异化提示、留痕和人工复核。

5. 保险
- 保险首先是风险管理工具；
- 保障型与储蓄／投资型功能必须分拆解释；
- 分红、万能、投连等产品的非保证利益、费用、退保损失和流动性必须明确展示。
