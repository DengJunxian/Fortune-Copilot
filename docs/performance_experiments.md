# 性能与七项发布实验

## 口径

所有结果固定标记为 `test`／`internal_demo`，仅描述合成数据、本地规则和授权测试协议，不代表中国工商银行真实客户、员工、系统性能、干预效果、经营效率或投资结果。协议与阈值来自 `data/benchmarks/demo_release_v1.json`，运行记录持久化在 `experiment_suite_runs`。

## 性能目标

| 环节 | 本地测试目标 | 计时边界 |
| --- | ---: | --- |
| 首屏 | < 5 秒 | 浏览器进入 `/demo` 到本地清单／三家庭结果可读；缓存命中可复用 |
| 初次诊断 | < 5 分钟 | 家庭加载、录入确认和财务诊断累计 |
| Monte Carlo 100 路径 | < 60 秒 | 创建并推进到完整孪生结果 |
| 正式报告 | < 60 秒 | 结构化八章、数字账本和快照写入 |
| 完整十阶段 Demo | < 5 分钟 | 主运行开始至审计闭合 |

这些是测试目标，不是生产 SLA。后端把各阶段单调时钟耗时、目标和逐项布尔结果写入 `DemoRun.metrics`；页面只展示服务端结果。三家庭对照使用家庭版本 + 分析日形成的 TTL 缓存键，重置／加载后立即失效。预热脚本提前读取场景、行为规则和受控知识，不向外网请求。

## 七项实验

| 编号 | 实验 | 自动化程度 | 当前可声明结果 | 不可声明内容 |
| --- | --- | --- | --- | --- |
| E01 | 计算与性能基准 | 自动实测 | 本地确定性结果与版本化标准答案一致；记录阶段耗时 | 生产吞吐或真实客户性能 |
| E02 | 适当性对抗 | 自动实测 | 明显不适当请求被三道闸门拒绝并审计 | 全部现实销售场景均已覆盖 |
| E03 | 政策问答 | 自动实测 | 回答只引用有效、适用、未隔离的受控切片 | 实时政策或法律意见 |
| E04 | Prompt 注入 | 自动实测 | 恶意切片／请求被扫描与治理终检拦截 | 对所有未知攻击永久免疫 |
| E05 | 用户理解度问卷 | 协议就绪，未实测 | 5 道题、同意、匿名响应和评分流程可执行；参与者数为 0 | 真实客户理解度、显著性或工行样本 |
| E06 | 行为干预 A/B | 合成／授权测试 | 四种分组、确定性分配和描述性指标可复现 | 因果效果、收益改善或真实转化率 |
| E07 | 客户经理流程时间 | 协议就绪，模拟基线 | 任务分解、计时点、模拟前后用时可执行；实测员工数为 0 | 工行员工效率提升或生产节省 |

整个实验套件必须恰有七项。E05 和 E07 返回 `protocol_ready`、`measured=false`；总体通过表示边界、协议和可自动验证项目齐备，不把未采样协议伪装为实证。`real_bank_results_claimed` 必须为 `false`。

## 用户理解度协议

参与前需单独同意，明确竞赛原型、合成数据、不构成建议与可随时退出。五题分别核对：信用卡额度、动态四账户、非保本边界、70% 分母，以及关键金额必须由确定性工具计算。最低工资／CPI 边界由政策问答实验另行核对。记录只允许匿名参与者散列、题目版本、答案、正确数、用时、退出状态和授权范围；不得收集真实账户或可识别财务资料。样本量、通过率和置信区间只有在真实授权测试完成后才能填写。

## 客户经理时间协议

任务固定拆分为资料核对、底表、异常识别、目标与账户、适当性、沟通稿复核、合规提交、报告和复盘。当前 JSON 仅含版本化模拟基线与辅助耗时，用来验证计时器和流程，不是员工观察结果。真实试验必须记录样本定义、培训效应、任务难度、人工复核质量和异常处理时间，并由机构授权后另行发布。

## 复现

```bash
curl -X POST http://127.0.0.1:8000/api/v1/demo/experiments/run \
  -H 'X-Actor-ID: local-review' \
  -H 'X-Actor-Role: compliance' \
  -H 'Content-Type: application/json' \
  -d '{}'
```

或运行 `make acceptance` 同时验证主 Demo 与实验账本。最终本机验证记录写入 `docs/progress.md`，以运行时返回值为准，不手工填造性能数字。
