# 客户理财规划产品前端审计

更新日期：2026-08-07

本轮按 `redesign-existing-projects` 的 Scan → Diagnose → Fix 执行，审计范围为首页、客户入口、家庭报表、比率分析、目标录入和规划书。

## Scan：现有界面

### 保留的有效部分

- 已有 React／TypeScript 组件、项目 token、ECharts 图表封装和无障碍基础。
- 财务数字有后端统一口径，已有格式化函数能保证金额、比率和日期一致。
- 已有客户、客户经理和风险角色的基础路由。
- 已有资产负债、收支、比率、目标与八章报告的实际数据。

### 阻碍客户使用的问题

| 问题 | 用户影响 | 严重度 |
| --- | --- | --- |
| 客户端一次展开 11 个任务工作区 | 不知道从哪里开始，无法建立完成预期 | 高 |
| 顶栏出现角色模拟、运行模式和技术状态 | 降低客户对产品的信任，也增加理解成本 | 高 |
| 首页优先讲解系统能力和设计理念 | 客户看不到自己要做什么和能得到什么 | 高 |
| 家庭资料和四张报表缺少统一填写流程 | 资料上传门槛高，难以独立完成 | 高 |
| 比率分散在多个技术工作区 | 结果、公式、参考范围和家庭解释无法同时核对 | 高 |
| 规划书的客户阅读路径不突出 | 主要交付物被内部证据和流程状态淹没 | 中 |

## Diagnose：根因

1. **信息架构以能力而不是人物任务分类**。后端有什么，前端就显示什么，没有为普通客户建立一条主路径。
2. **产品文案说明内部实现，没有支持当前操作**。客户需要的是资料准备、填写口径、结果含义和下一步。
3. **财务引擎的领域模型没有客户输入适配层**。直接暴露底层分类会让表单过长且术语化。
4. **产品和内部工作区缺少层级隔离**。客户、顾问和风险人员的信息密度与决策任务不同。

## Fix：已实施

### 产品导航

- 客户端默认导航收敛为“首页”和“开始规划”。
- 客户经理、风险与高级客户工作区仅在内部路由显示。
- 移除客户端可见的模型状态、账号模拟选择器和技术性提示条。

### 首页

- 首屏直接说明“从家庭财务报表开始”和产出“家庭理财规划书”。
- 使用真实的财务报表视觉摘要，不使用虚构科技界面。
- 把五步流程和六项比率作为主要信息，用户可预期需要准备的资料和最终结果。
- 加入职业起步、双收入育儿和退休准备三类人物，每类都可进入完整流程。

### 填写与分析

- 新增五步 `PlanningJourney`，支持草稿自动保留和返回修改。
- 家庭报表提供中国家庭理财常用默认项，并支持自定义行。
- 财务分析页先显示四个总额，再显示图表和六项比率，从概览逐步下钻到公式和解释。
- 模型解释与本次公式、代入和参考范围同卡展示，并明确数字来自财务报表计算。

### 规划书

- 客户阅读视图使用固定八章侧边目录，桌面像正式文书，手机改为顺序阅读。
- 家庭阶段、资产类别、负债类别和收支类别统一显示中文，不泄露内部枚举值。
- 第七章先给资金使用顺序和风险边界，再承接已经实现的具体基金说明；产品层不能反向修改家庭规划金额。

## 视觉校准

| 维度 | 旧界面 | 新产品 |
| --- | --- | --- |
| 视觉重心 | 证据链、技术状态、多工作区 | 家庭财务事实、比率和下一步 |
| 导航 | 高密度任务标签 | 一条五步流程 |
| 文案 | 解释实现方法 | 说明用户任务与资料口径 |
| 色彩 | 多角色、多状态色 | 暖白、深墨、单一品牌红 |
| 图像 | 功能界面截图为主 | 真实家庭人物与财务报表视觉 |
| 信息密度 | 所有层级同时展开 | 概览→结构→比率细节渐进展开 |

## 真实浏览器验收

- 1440px 桌面首页：首屏主行动、财务摘要、五步流程和三个客户案例层级清晰。
- 390px 手机首页：主标题、操作和财务预览为单列，不存在文档级水平溢出。
- 390px 家庭情况表单：标签、输入、成员编辑和主行动在触控尺寸下可完成。
- 1440px 双收入家庭比率页：六项结果、公式、代入、范围和解释均可见。

视觉规范以项目根目录 `DESIGN.md` 为准。

## 2026-08-06 增量审计：智运财富与动态四账户

本次再次按 `redesign-existing-projects` 执行增量 Scan → Diagnose → Fix，并结合 `design-taste-frontend` 做客户入口、长表单和正式规划书的视觉校准。Design Read 为：面向中国普通家庭的真实银行财富规划产品，暖白、深墨、单一品牌红，低动效、中等信息密度，先让客户核对家庭事实，再展示规则结论和行动顺序。

### Scan

- 旧品牌与部分工程化英文仍出现在产品标题、报告封面和接口元信息中。
- 基本情况页缺少地区启动线、资金来源、投资经验、风险偏好、波动承受和投资期限。
- 首页没有把中国家庭四账户讲成可理解的处理顺序。
- 第七章只有通用行动清单，没有显示客户本次启动线、四账户金额、70% 分母和购买力观察门槛。
- DeepSeek 可以解释比率，但尚未形成第 1—3、5—6 章的统一结构化讲解链路。

### Diagnose

1. 四账户理念没有变成客户可填写、后台可计算、规划书可核对的统一契约。
2. “保本的钱”与“生钱的钱”若只展示比例，会产生产品保本或家庭总资产统一配置的误解。
3. 大模型若直接组织第七章，可能把“70% 条件未满足”误写为“完全不启用增长层”，与确定性建议金额冲突。
4. 桌面账本需要同时容纳当前金额、建议金额和产品教育；手机必须改为纵向顺序且不产生页面级横向滚动。

### Fix

- 品牌统一为“智运财富”，副标“普慧金融”，英文名“Fortune Copilot”。
- 基本情况页新增客户识别与适当性区，地区切换联动 30万—100万元滑块，资金来源使用可多选的明确标签。
- 首页新增纵向四账户账本与启动线入口，明确比例随家庭变化。
- 八章规划书新增适当性摘要、目标准备进度、大额支出时间线、资产分布和完整四账户账本。
- 第七章同时显示可规划金融净值、客户选择的启动线、账户当前／建议金额、市场档位、5%—30% 总观察带、当前战术锚、70% 适用分母、购买力观察门槛和行动顺序。
- 保本资金新增偏积极／中性／偏防守三档确定性规则；真实建议金额只移动满足前置条件后的长期资源，家庭目标和安全缺口不会被市场判断覆盖。
- DeepSeek 负责第 1—3、5—6 章的解释；第七章关键账户文字强制回到确定性规则原文。
- DeepSeek 的复核触发条件同样接受确定性终检，避免模型把已通过的启动门槛写成未通过。
- 1440×900 与 390×844 真实浏览器检查均无文档级水平溢出，控制台为 0 个错误、0 个警告；第七章已实机显示“中性 10%—20%、战术锚 15%”及家庭目标优先边界。

### 2026-08-06 增量复核：学习仓与窄屏章节阅读

**Scan**

- 未达正式启动线时，第七章只有“暂不启动”结论，无法承载客户提出的小额投资学习需求。
- 一段式四账户说明同时塞入金额、门槛、70%与购买力口径，阅读像规则播报，不像客户投资者教育。
- 390px 手机滚动到规划书后切换章节，双层吸顶可能盖住新章节标题；五步进度使用 34rem 最小宽度，必须横向拖动。

**Diagnose**

1. 正式配置与学习仓需要两个确定性状态，否则前端文案容易把 10% 上限误写成正式配置比例。
2. 第七章应先回答客户“我现在该做什么、为什么、做到什么程度”，规则证据留在结构化卡片中。
3. 章节切换应主动滚回带吸顶避让的正文起点；移动进度应在 320px 以上同屏可读。

**Fix**

- 新增学习仓卡片，显示金额、实际比例、10%上限、多余长期资金分母和未通过条件；正式 70% 边界保持独立。
- 四账户说明改为三段投资者教育文字，明确学习宽基指数基金的波动、费率、持有期限与降仓条件。
- 章节按钮与上下章统一调用滚动定位，正文增加 `scroll-margin-top`；手机端五步进度改为图标与标签上下排列并取消横向最小宽度。
- 对账户说明、行动清单、学习仓和窄屏数据列增加 `min-width: 0`、自动换行与单列降级，避免金额和长中文相互覆盖。

## 2026-08-07 增量审计：投顾接入后的客户产品重构

本次继续按 `redesign-existing-projects` 执行 Scan → Diagnose → Fix，使用 `design-taste-frontend` 校准银行金融科技视觉，以 `de-AI-writing` 清理客户文案，并用 Playwright 走完真实客户路径。Design Read 为：面向普通中国家庭投资者，银行级、克制可信、中文为主；视觉变化度 4、动效强度 2、信息密度 6。

### Scan

- 首页三个公开客户案例会直接进入 `/client/advanced` 的 11 个内部工作区，客户看见的是系统能力而不是自己的规划流程。
- 新接入的基金投顾默认展开产品目录、候选、规则、渠道证据和内部限制，信息量超过客户当前决策需要。
- 客户可见文案混入“安全闸门、守门、确定性规则、Mock 产品、真实基金证据”等研发和复核语言。
- 基金目录路径未注入 Compose 运行环境，第七章请求会返回 500，并显示醒目的技术故障提示。
- 原有视觉虽已使用品牌红，但投顾组件的卡片层级和状态语言与正式规划书不一致。

### Diagnose

1. 智能投顾按后台能力接入，没有先确定它在客户旅程中的位置。具体产品只能是第七章的下一层说明，不能成为独立主入口。
2. 同一套接口内容直接服务客户与内部复核，导致来源、求解和限制说明泄露到客户页面。
3. 文案强调系统如何判断，没有先回答投资者“这笔钱做什么、金额多少、会承担什么风险、下一步怎么做”。
4. 投顾组件缺少与主产品一致的账表式视觉和移动端降级规则。

### Fix

- 公开案例统一进入 `/planning`，客户主路径固定为家庭情况、财务报表、财务分析、目标计划和八章规划书；内部高级工作区继续保留但不进入公共导航。
- 将具体基金说明嵌入第七章，先显示资金用途、本次金额、风险承受范围和家庭准备情况，再展示产品名称、代码、金额、比例、风险与购买前核对；产品资料来源默认折叠。
- 面向客户重写首页、比率解读、第七章和基金卡片文案。先说家庭责任与行动，再说明波动、费用、持有期和退出条件；删去内部系统术语和答辩式理念说明。
- 视觉采用暖白、深墨、单一银行红、细分线和账表式数字层级，保留项目自有“运”字标，不使用工商银行官方标识。
- Compose 增加基金目录挂载路径，主 Demo 的第七章已恢复真实响应。
- 基金理由按货币基金、债券基金、宽基指数和个人养老金分别讲解，不把任何基金写成保本产品；无法确认渠道或不符合家庭条件时，用客户能理解的原因说明资金继续保留。
- 移动端把投顾摘要、产品卡片、购买确认和页脚统一降为单列，长产品名、代码和金额允许自然换行，不产生页面级横向滚动。

### 设计结论

“构建中国自主的财富管理体系”不再作为客户页面上的反复口号，而是通过住房、养老、子女教育、父母赡养、收入稳定性、地区启动线和动态四账户的实际录入与计算体现。产品视觉参考工商银行金融科技产品的秩序感，但品牌、标识和内容均保持“智运财富｜普慧金融｜Fortune Copilot”自身识别。
