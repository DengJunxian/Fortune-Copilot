# 无障碍规范

目标：核心三端达到 WCAG 2.2 AA，并在金融风险表达上避免只靠颜色或动效传递含义。

## 键盘

- 每个页面首个 Tab 为“跳到主要内容”。
- 导航、表单、表格操作、抽屉、对话框和图表数据表均可只用键盘完成。
- focus-visible 使用 3px 高对比焦点环和 3px 间距，不移除浏览器焦点而不提供替代。
- 对话框打开时聚焦标题或首个有效操作，关闭后回到触发器；Esc 只关闭非阻断浮层。
- 客户端任务切换后将焦点移到新任务主标题；11 项任务标签采用 roving `tabIndex`，支持方向键、Home 和 End。

## 语义与读屏

- 使用 header、nav、main、section、aside、table、dl 等语义元素。
- 页面只能有一个当前主标题；区域标题通过 aria-labelledby 关联。
- 状态使用可读文字，颜色只作为辅助。
- 图表提供文字结论、读屏摘要和等价数据表。
- 输入必须有持久标签；错误信息与字段关联；placeholder 不承担标签作用。
- Mock、合成数据、估算值、过期数据和模型降级都需要读屏可见说明。
- 关系图的 `title` 只提供稳定图名，详细说明通过 `aria-describedby` 关联；同一数据必须有语义表格替代。
- 政策引用按有序列表朗读机构、版本、发布／生效／核验日期与段落；外链名称包含文档标题。
- 自然语言提取项使用 `fieldset`、持久标签和独立复选框；“已提取”“已确认”和“仍缺失”不能只靠样式区分。
- 九智能体步骤使用有序列表，序号、名称、工具、禁令、超时和终态均进入可访问名称或相邻文本。
- ECharts 外层使用稳定的 `role="img"` 与图名，内部动态 SVG 从辅助技术树隐藏；同源精确数据通过可展开语义表格提供。
- 金额遮罩直接卸载敏感工作区；原始金额不得残留在 `aria-label`、title、隐藏文本或 ECharts 节点中。
- 八章规划书使用具名章节导航；章节状态、依据、引用和边界均可按 DOM 顺序阅读。

## 视觉

- 正文对比度不低于 4.5:1，大字不低于 3:1。
- 主操作、输入与导航触控目标至少 44×44 CSS px。
- 金额和比例使用 tabular nums，避免位数变化造成视觉跳动。
- 风险、预警、通过和完成同时使用文字或图标，不仅使用红橙绿。
- 支持 200% 浏览器缩放和大字模式；内容不得重叠或横向截断。
- 深色与大字模式由根级 data attribute 驱动，图表主题与正文主题同步，不在单图硬编码浅色文字。

## 动效

- 默认动效 150-250ms，只用于反馈、层级和状态变化。
- prefers-reduced-motion 下关闭非必要动画和 smooth scroll。
- 核心流程禁止滚动劫持、持续视差、磁吸按钮和长时间自动动画。
- 计算中状态必须有文本，不能只靠旋转或闪烁。

## 响应式

- 验证 1366×768、1440×900、1920×1080、平板和手机。
- 表格窄屏允许横向滚动，并用 role=region 和标签说明；不得隐藏关键风险字段。
- 关系图 1180px 画布和数字账本仅在有标签的组件区域横向滚动，document/body 宽度必须保持等于视口。
- 多列布局在 1024px 和 768px 处显式折叠。
- 移动导航保持当前位置和三端入口，不用 hover 才能发现操作。

## 自动与人工检查

- Vitest 使用 axe-core 对入口页做自动扫描。
- Playwright 验证跳到主内容、三端导航、离线页面、11 项任务键盘导航、图表等价表、金额遮罩、八章导航、合规阻断、reduced-motion、受控政策来源、逐项确认、关系图和九智能体步骤。
- 每阶段人工检查焦点顺序、200% 缩放、reduced-motion、浅/深模式和主要断点。
- 自动扫描不能替代金融文案、图表口径和读屏顺序的人工作业。

Stage 9 已在 390×844、1366×768、1440×900 和 1920×1080 检查文档横向溢出；任务标签、图表和表格只允许在具名内部区域滚动。单元测试使用 axe 扫描客户端财务健康入口，真实浏览器回归同时记录控制台错误与外部网络请求。

Stage 10 将模拟账号放在三端主导航之后，原生 `select` 具备“模拟账号”标签和边界说明。顾问端焦点顺序为客户队列→面谈底稿→候选选择→人工高风险确认→沟通稿→版本动作；风险端为待审队列→控制矩阵→审核理由→人工复核→审核动作→投诉回放→审计导出；客户端为状态轨→三项确认→演示签署姓名→确认。八状态步骤轨使用有序列表和 `aria-current="step"`，不能点击跳步；高密度表格仅在具名 `role="region"` 内横向滚动。

真实 Compose 的 Playwright 三端闭环使用键盘可操作的原生表单控件，记录控制台 0 error／0 warning、外部请求 0；人工查看 1366×768 顾问端、1440×900 风险端和 390×844 客户确认区。移动端保留状态文字、当前第几步、Mock、非保本和不可交易边界，不仅依赖红／橙／绿色。
