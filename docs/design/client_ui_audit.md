# 客户端与三端 UI 审计

协议：redesign-existing-projects 的 Scan → Diagnose → Fix

## Design Read

Reading this as: 受监管金融产品的绿地工程底座，服务中国家庭、客户经理和合规审核员，采用可信、克制、中文优先的产品语言，依托项目自有 token 与原生 CSS，动效保持低强度。

设计拨盘：客户端 4/3/5；顾问端 3/2/7；风险端 2/1/8。

## Scan

审计开始时仓库为空，没有框架、样式、品牌 token、组件、页面树、导航、内容块、SEO 元数据或交互。没有旧路由、表单字段、分析事件、法律文案和品牌资产可保留。

模式判断：Greenfield。用户要求先审计现有前端；审计结果是“现有前端不存在”，因此不存在有依据的 preserve 或 overhaul 操作。

## Diagnose

空仓对应的实际缺口：

1. 没有品牌目标、语义色彩、中文与数字排版、间距、圆角、层级或密度。
2. 没有客户端、顾问端、风险端信息架构和共享导航。
3. 没有 Loading、Empty、Error、Offline、Degraded、Blocked 状态。
4. 没有键盘焦点、跳转链接、读屏语义、触控目标或 reduced-motion。
5. 没有能力边界，容易把 Mock、计划能力或未计算数字显示成真实结果。
6. 没有响应式规则、404、错误边界或 API 离线降级。
7. 没有设计来源追踪，直接实现会产生品牌复制和模板化风险。

由于没有旧代码，以下常见问题不能被声称“发现于旧页面”：三等分 AI 功能卡、死链、假用户、错误字体、图表误导、硬编码金额、无状态按钮。它们作为预防性检查进入 Fix 和验收清单。

## Fix

- 建立根 DESIGN.md 作为唯一视觉规范源。
- 研究 IBM、Revolut、Linear 后创建原创低饱和深蓝、品牌红、暖金体系。
- 创建 tokens.css，包含浅/深模式、三端密度、数字字体、层级和 reduced-motion。
- 使用顶部任务导航，避免默认左侧栏；三端共享 AppShell 和 active state。
- 创建 /client、/advisor、/risk 和 404，所有入口都有返回路径。
- 使用分区、流程行与表格，不使用三张等宽营销卡或大圆角阴影拼贴。
- 加入跳到主要内容、focus-visible、44px 触控目标、语义表格和横向滚动区域说明。
- 加入 ErrorBoundary 与 API 离线 Mock 提示。
- 可见内容不使用伪造家庭金额，不用绿色表达预计收益。
- 固化竞赛原型边界和七项金融红线。

## 阶段 1 Pre-flight

- 主题：系统浅/深模式，全页一致。
- 色彩：单一品牌深蓝锚点，品牌红仅主操作/关键强调；语义色有文字。
- 形状：控件 6px、容器 10px，状态徽标不用无意义胶囊。
- 导航：桌面单行；窄屏横向滚动；aria-current 由 NavLink 管理。
- 动效：只有 150-220ms 状态反馈，reduced-motion 可关闭。
- 内容：无 Lorem Ipsum、假客户、假金额、外部图片或 # 死链。
- 组件：无虚构 import，所有依赖写入 package.json。
- 状态：阶段 1 建立全局错误、404 与 API Offline；阶段 9 已补齐客户端 14 类领域状态和真实降级／阻断路径。
- 测试：Vitest、axe-core、Playwright 已建立，实际结果记录在 docs/progress.md。

## 阶段 3 财务驾驶舱审计

视觉命题是“可核验的家庭财务工作底稿”：克制、账本化、证据优先，不使用卡片拼贴或装饰性行情图。内容顺序锁定为家庭总览 → 五张底表 → 全量指标 → 保障／购买力 → 数据诊断；交互主线是选择指标 → 查看公式与证据 → 返回原账本。

Scan 发现阶段 1 客户端仍是方法占位，不含真实底表、指标和局部 Loading／Error；这是提示词 3 的实际缺口。Fix 已完成：

- 连接 A／B／C 家庭与确定性分析 API，默认主 Demo B；
- 用四行指标账本与七维辅助雷达构成总览，雷达明确“非监管评级”；
- 用语义 tabs 容纳五张底表，窄屏保留横向滚动而不静默删列；
- 20 项指标逐行显示当前值、代入、参考条件、来源类型、文字状态与审计入口；
- 抽屉支持初始焦点、Tab 闭环、Escape 关闭和焦点恢复；
- 无后端时显示 blocked/error 和合规边界，不加载测试标准答案；
- 提供 JSON 导出与显式保存运行反馈；
- 桌面 1440px、移动 390px、离线预览与 Compose 连接模式均完成浏览器回归。

视觉回归纠正了“数据完整度 0–100 分被当作 0–1 比率”的显示错误，并将底表技术枚举翻译为中文。所有风险继续使用“文字 + 语义色”，品牌红只用于主行动和审计入口。

## 阶段 4 目标与四账户审计

本阶段重新调用 `redesign-existing-projects` 的 Scan → Diagnose → Fix，对阶段 3 已有客户端做增量改造，没有替换 React／TypeScript／原生 CSS 技术栈。

Scan 确认已有顶部任务导航、家庭选择、财务元数据、账本式指标、五表与审计抽屉。需保留其信任语言、密度和路由；不适合将四账户拆成四张等宽卡片或另建营销风页面。

Diagnose 定位的真实缺口是：客户无法录入目标；无法同时对照当前与建议值；缺少三种分母、七步流程、限制因素、70% 条件、反事实和行动优先级的可视证据。

Fix 采用“规划工作底稿”视觉命题：

- 在财务底表前加入目标与安全闸门，强化“先安全、后增长”的阅读顺序；
- 四账户使用纵向账本行与窄色线识别，不用固定比例环图或卡片拼贴；
- 金额、家庭总资产、可投资金融资产、年度新增结余四种显示口径共用同一账本结构；当前和建议比例都直接来自 API；
- 生命周期依据、账户公式、三尺、5%—30% 参考带与 70% 条件使用可展开的审计层，默认不压过主任务；
- 目标时间轴保留未来金额、已准备、缺口、月投入、刚性和可延期性；冲突使用暖色边缘与文字调整组合；
- 反事实表单就地展示原方案与重算结果，不使用等待旋转来掩盖数字来源；
- 桌面 1440px 和移动 390px 已完成真实 Compose 视觉回归；窄屏把账本列按任务顺序堆叠，保留缺口、条件和展开证据。

阶段 4 没有引入外部图片、行情装饰、随机布局、滚动劫持或重动效。保本账户仍使用“期限匹配与本金安全偏好”文案，不表达任何产品保本。

## 阶段 5 组合与适当性审计

本阶段再次依照 `redesign-existing-projects` 执行 Scan → Diagnose → Fix。Scan 确认三端已有统一顶部导航、项目 token、财务与规划账本、窄屏堆叠和 Mock 边界，继续保留 React／TypeScript／原生 CSS，不更换设计系统。

Diagnose 发现的核心缺口不是“缺少三张方案卡”，而是用户无法横向核验同一指标，资产比例、产品映射、三道闸门、求解降级和再平衡之间缺少连续证据。若把稳健／基准／进取做成三张等宽卡片，会放大营销观感并迫使用户来回扫描。

Fix 采用“候选比较矩阵 + 纵向证据账本”的视觉命题：

- 三候选共享行标签，对齐决策、金额、目标成功率、情景区间、极端损失、回撤、流动性、费用和求解方法；
- 选中候选后按资产类别展开原生 `progress` 比例、金额和战术差异，不用收益导向的饼图或炫技动效；
- 家庭、客户、产品三闸门按因果顺序组成证据链，每项显示文字状态、观察值、规则、原因和来源，不只靠颜色；
- Mock 产品映射与完整目录持续显示风险、期限、流动性、费率和保证／非保证披露，不能误认为工行在售产品；
- 客户端突出“当前无可执行长期资金”及补回安全层金额，避免教育候选被误读为交易建议；
- 顾问端提供同一候选矩阵和保存草稿，风险端提供五种对抗探针及返回的审计事件 ID；
- 市场情景控件明确最多 5pp，家庭安全阻断时配置不因 risk-on 扩张；专业对冲实验室保持关闭、只读教育；
- 断网时继续显示 blocked 能力边界，不在前端嵌入标准答案或本地优化器。

真实 Compose 的 1366×768、1440×900 与 390×844 视觉回归属于阶段验收；窄屏将比较矩阵保留为可滚动语义表，把资产和闸门证据按阅读顺序堆叠，不隐藏金额、决策、Mock 标签或拒绝理由。

## 阶段 6 数字孪生与压力测试审计

本阶段再次执行 `redesign-existing-projects` 的 Scan → Diagnose → Fix，并按 `visualize-data` 检查图表选择、数据契约和无障碍降级。Scan 确认阶段 5 已有证据账本、比较矩阵、项目 token、三端密度和 Mock 边界；继续保留 React／TypeScript／原生 CSS，不引入网络图表依赖。

Diagnose 发现的真实缺口是：家庭未来只能通过静态情景区间理解，无法查看路径分布、失败时间、最差路径和原／优化方案的同 seed 差异；三端也没有运行进度、取消、参数哈希与场景版本。单根折线会暗示确定增长，三张等宽 KPI 卡会割裂同一概率口径，装饰性图表则无法核对精确值。

Fix 采用“一个主扇形 + 一个概率账本 + 一列场景证据”的视觉命题：

- 主图使用 P10—P90 外层、P25—P75 内层和 P50 实线，显示零轴、直接标签、标题、口径、路径数、seed、期限、单位、来源、文字结论和读屏摘要；
- 图表下提供完整精确数据表，负净资产和尾部结果不会被坐标裁掉；无足够时间点时显示明确空状态；
- 基线、原压力、优化压力使用同一行列矩阵对齐目标成功、耗尽、被迫出售和期末分位，不拆成营销卡；
- 原／优化扇形可切换，文案只在实际差值为正时说“减少被迫出售”，不把优化预设为有效；
- 每个场景用八项证据回答应急月数、最先失败目标、出售、保障缺口、退休延后、可压缩支出、新增储蓄和成功率变化；
- 客户端强调理解目标路径，顾问端强调反事实比较，风险端默认展开 seed、版本、参数哈希、数值校验和审计事件；
- 场景、退休、储蓄、权益、流动性、房价、收入、教育、医疗、失业和基础假设均有显式控件；覆盖值进入后端哈希，前端不计算金融结果；
- 运行状态用原生 progress 与文字阶段表达，取消后不保留部分结论；Mock 无外部网络仍能完成主路径。

色彩沿用单一低饱和深蓝信息根，外／内分位层以透明度和边界线同时区分；预计收益或高成功率不使用绿色庆祝。移动端保留可横向滚动的 SVG 和数据表，控制项单列，所有关键金额、条件、版本和取消动作仍可访问。真实 Compose 视觉回归结果记录在 `docs/progress.md`。

## 阶段 7 行为金融双画像与干预审计

本阶段按 `redesign-existing-projects` 再次执行增量 Scan → Diagnose → Fix。Design Read 将页面识别为高信任行为实验与证据底稿：客户端的核心任务是完成选择并理解配置上限变化，顾问端是对照说法与选择，风险端是复核冲突、干预和实验指标；密度继续为 5／7／8，动效只服务于选择进度与状态反馈。

Scan 确认阶段 6 已形成统一顶部导航、项目 token、账本、比较矩阵、三端密度、Mock 边界和移动端横向证据区。应继续保留 React／TypeScript／原生 CSS 和“数字可追溯”的信任语言，不能另起通用卡片式心理测评页面。

Diagnose 定位到五类实际缺口：缺少可退出的七维问卷／六项实验；自述、实验与客观能力不能对照；偏差分数没有来源会沦为人格标签；冷静期和干预状态缺少审计时间；A/B 配置与合格数据范围对风险端不可见。移动端还必须在不依赖颜色的前提下保留冲突、证据、选择与退出。

Fix 采用“选择步骤 + 四层风险账本 + 偏差／干预证据列”的视觉命题：

- 实验入口用可展开七维滑杆；进行态一次只显示一个 `fieldset`，原生 progress 展示已持久化数量，“退出实验”始终可见；
- 完成态单独呈现 6／6，避免把终态错误显示为选择 7／6；响应表对齐选择、反应时间、修改次数、一致性与解释；
- 双画像以四条纵向账本显示客观能力、问卷、实验和最终上限，不平均、不使用仪表盘美化风险；强制冲突代码直接可核验；
- 十一项偏差沿同一纵向证据列表展示文字级别、原生 progress、来源、贡献与解释，颜色只作辅助；
- 干预列显示场景、触发偏差、家庭目标、状态、24／48 小时开始与可操作时间；未到期按钮明确禁用，用户仍可暂不采用；
- 风险端默认展开四组 A/B 配置、分配／完成／退出／下调／干预指标和“仅合成／授权测试”的边界；
- Loading、Error、信息不足、进行中、完成、退出和冷静期阻断均有独立文字状态；断网时不从家庭资产猜测偏差或嵌入标准答案。

布局使用整段账本与紧凑证据行，不把十一项偏差或四组实验拆成泛化卡片网格。键盘可完成问卷、六项选择、退出和展开证据，axe 自动检查纳入前端测试；真实 Compose 的桌面与 390px 移动视觉回归结果记录在 `docs/progress.md`。

## 阶段 8 受控知识、关系图谱与九智能体审计

本阶段依照 `redesign-existing-projects` 再次执行增量 Scan → Diagnose → Fix。Design Read 将新增区域识别为“政策来源与运行证据底稿”：客户端首先核对解释来源和录入草稿，顾问端核对家庭关系与缺口，风险端核对九步工具调用和终检；继续使用 5／7／8 的三端密度与项目既有低动效规则。

Scan 确认阶段 3—7 已形成统一导航、token、纵向账本、证据矩阵、可访问 SVG／表格降级、Mock 标识和移动端内部滚动。现有前端结构足以增量扩展，不需要改框架、引入聊天 UI 套件或建立另一套 AI 视觉系统。

Diagnose 定位出六类缺口：政策解释没有来源日期账本；自然语言无法区分“已提取”与“已确认”；家庭关系和限制因素分散在多处；智能体目录可能被误认成真实调用；模型降级／政策过期／提示注入缺少独立状态；复杂关系在手机上容易造成整页横向溢出。

Fix 采用“政策引用账本 + 五列关系图 + 九步运行时间线”的视觉命题：

- 受控 RAG 先显示文档／切片／隔离数量和运行时网络边界，再显示答案、查询日、过滤数量、机构、版本、发布／生效／核验日期、段落、地区和来源；
- 自然语言入口保留默认示例，但解析后每项使用复选框、可编辑确认值、原文证据、单位和置信度；缺失项折叠区解释为何不能从月供猜房贷余额；
- 图谱固定五列“家庭关系—事实底稿—目标期限—风险约束—政策产品”，节点与连线只表达关系；六项推导另用编号账本陈述规则和证据；
- SVG 使用独立可访问标题和描述，下面提供完整节点表；1180px 画布只在 `.relationship-canvas` 内部滚动，不让 document/body 超出视口；
- 风险端初始明确“尚无真实调用链”，点击运行后才按 01—09 显示名称、Schema、工具、禁令数量、超时预算和步骤状态；数字账本在终检结果之后渐进披露；
- Loading、Empty、Error、Degraded、Blocked、过期、隔离和信息不足均有文字，不用颜色或 AI 光效替代；外部模型与网络不可用时仍显示 Mock 完整链；
- 延续深蓝／暖金／品牌红的项目语义色、6px 控件圆角和账本分隔；没有新增营销卡片阵列、紫蓝渐变、机器人头像或伪聊天气泡。

组件测试包含 SVG 可访问名称、axe、政策日期、逐项确认和九步链；真实 Compose 的 1366×768 客户端、1440×900 顾问端和 390×844 风险端视觉回归与溢出检查记录在 `docs/progress.md`。

## 阶段 9 客户端完整体验审计

本阶段再次执行 `redesign-existing-projects` 的增量 Scan → Diagnose → Fix。Design Read：面向普通家庭、顾问与风控人员的受监管财富管理产品界面，克制、可信、账本式；沿用 React、TypeScript、原生 CSS 与项目 token；低动效、中密度、低视觉偏差；信息可核验优先。

### Scan

阶段 3—8 已经形成财务、规划、组合、孪生、行为和可信 AI 六个完整工作台，三端共享 AppShell、账本、比较矩阵、语义表格、读屏替代、Mock 边界和移动端内部滚动。它们是需要保留的产品资产，未发现更换框架、重置品牌或复制外部设计系统的依据。

实际缺口集中在跨能力体验：客户端仍以纵向堆叠为主，缺少明确的全旅程与任务导航；家庭画像、报告、行动和隐私没有独立入口；图表实现分散；显示偏好没有统一状态；Loading 到 ReportFailed 的完整状态缺少集中验收；A／B／C 切换虽存在，但没有把三者的图表和行动差异纳入契约。

### Diagnose

1. 单页堆叠使普通家庭难以理解“现在在哪、下一步是什么”，移动端也需要跨越大量内容。
2. 资产负债、现金流、目标和预测图表缺少统一标题／口径／单位／来源／数据表协议。
3. 只用 CSS 隐藏金额会让原值留在可访问树，隐私模式必须从组件树卸载敏感内容。
4. 深色、大字、低金融知识、金额／比例和元／万元若各自局部实现，会出现口径和主题漂移。
5. 报告与行动若在浏览器临时拼数字，会越过“LLM 与前端都不计算关键金融数字”的边界。
6. 隐私撤回、删除和人工复核需要版本冲突、二次确认与明确终态，不能依赖无动作按钮。
7. ECharts 若直接暴露其动态 SVG 节点，读屏名称会重复且不稳定；需要固定外层图名和等价表格。

### Fix

- 将客户端重组为 11 个任务工作区，保留原有六类工作台作为可组合内容，不重写确定性业务逻辑；13 步旅程账本负责显示完成、可进入、需行动和阻断原因。
- 新增后端客户端聚合服务，将财务、规划、受控知识、授权、行动和八章预览在同一版本响应中组合；前端不自行计算金额或行动优先级。
- 建立本地模块化 ECharts SVG 基元，统一图表元数据、图例、文字结论、Loading／Empty／Error、reduced-motion 和精确数据表。
- 用共享 Context 管理显示偏好；金额遮罩直接卸载敏感工作区，深色图表使用项目自有语义主题，元／万元只改变格式化。
- 报告预览严格固定八章，并让尚未运行的数字孪生章保持 `pending_twin`；行动日历同时保留规则行动与 12 个月可核验复盘。
- 隐私中心提供 JSON 数据包、版本化撤回、软删除二次确认和人工复核；危险操作使用独立视觉层级。
- 完整状态预览明确标注为合成 UI Demo；真实离线、降级、阻断和失败路径不补造业务数据。
- 在 390×844、1366×768、1440×900 与 1920×1080 验证文档无横向溢出，并核对键盘 roving tab、reduced-motion、深色、大字、遮罩和外部请求为零。

### 十一页逐页 Design Read

| 工作区 | 一行 Design Read |
| --- | --- |
| 家庭画像 | 面向第一次进入的家庭决策者，用中密度责任关系树建立“这是我的家庭事实”信任，再给出最少的三条下一步。 |
| 资产负债 | 面向核对家底的家庭成员，用低偏差横向条形与底表证明资产、负债和净资产来自同一会计口径。 |
| 家庭现金流 | 面向寻找结余去向的家庭成员，用零轴瀑布和互斥分类解释钱从哪里来、被什么占用。 |
| 财务健康 | 面向需要先看结论再追证据的普通用户，用辅助雷达定位薄弱面，并让 20 项指标逐条回到公式。 |
| 动态四账户 | 面向准备行动的家庭，用顺序式资金瀑布和闸门证据说明四账户为何因家庭而异，绝不呈现固定四等分。 |
| 目标时间轴 | 面向协调教育、住房与养老冲突的家庭，用期限轴和同版本反事实比较优先级与准备缺口。 |
| 数字孪生 | 面向理解不确定性的家庭与顾问，用分位数扇形、共同随机数和压力账本替代承诺式单线预测。 |
| 行为实验 | 面向核对“说法和选择是否一致”的家庭，用单题步骤与四层风险账本降低人格评判感。 |
| 家庭规划书 | 面向复盘与交付的家庭，用严格八章、计算依据和引用导航形成正式但不虚构完整度的阅读体验。 |
| 行动日历 | 面向把规划落地的家庭，用立即／三月／一年／长期和月度复盘分层，不用收益激励或倒计时。 |
| 隐私中心 | 面向关注数据控制权的家庭，用授权账本、导出、二次确认和人工入口呈现可撤回、可追踪的边界。 |
