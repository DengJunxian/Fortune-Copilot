# 提示词 13 完整 Demo 前端审计

本轮按 `redesign-existing-projects` 的 Scan → Diagnose → Fix 协议完成，保留项目既有 React／TypeScript／Vite、`DESIGN.md`、设计令牌、Button／StatusBadge、三端信息架构和无障碍约束。

## Scan

- `/client`、`/advisor`、`/risk` 已是真实可操作工作区，共享 AppShell、角色选择、Mock 状态和本地 API；不需要框架迁移。
- 视觉语言以工作底稿、表格、证据账本和低强度状态色为主，已有深色、大字、低金融知识、键盘和移动端规则。
- 缺口是没有跨模块的比赛入口：观众需要在多个工作区自行拼接剧情，A／B／C 差异、十阶段进度、性能、实验边界和恢复状态也没有统一落点。
- 首页仍只列三端，无法把“一键演示”与三端人工复核关系讲清。

## Diagnose

新增页面应是“发布编排记录”，而不是另一套营销卡片驾驶舱。最重要的阅读顺序是：控制动作 → 逐阶段进度 → 决策数字 → 三家庭反例 → 实验边界 → 发布资产。三端继续承担细节编辑和人工复核，Demo 页只显示真实服务结果并提供转交入口。

必须避免：固定比例饼图、把四账户画成等大象限、装饰渐变、外部素材、虚构加载结果、用颜色单独表示通过，以及把协议就绪写成真实实验成功。

## Fix

- 新增 `/demo`，默认演示管理员角色；主导航和首页增加显式入口，但保留 client／advisor／risk 三个核心产品端。
- 建立操作轨道，分别支持幂等加载、合成数据重置、本地预热、一键完整运行、七项实验和失败运行重试。
- 用纵向十阶段时间轴展示状态、服务端进度和实际毫秒耗时；阶段完成即落库，失败保留证据。
- 用数值账本和横向表格展示净资产、房产集中、保障缺口、应急月数与四账户金额；70% 边界以文字列固定展示。
- 用 A／B／C 对照表呈现各户生命周期、安全月数、四账户金额和唯一配置签名，明确 `fixed_ratio_model=false`。
- 七项实验按“本地通过／协议就绪”和“已测量／未宣称实测”双轴展示，用户理解度与顾问时间不会伪装成工行结果。
- 发布区读取后端 manifest，不用前端硬编码“已齐备”。后端不可达时保留静态边界与错误说明，不显示家庭金额。
- 响应式布局在 72rem／48rem 断点收束；宽表保持可横向滚动，移动端时间轴保留文字状态。所有操作使用原生 button，表格有 caption／scope，状态区域使用 `aria-live`。

## 验证契约

- Vitest + axe 校验页面结构、三个唯一签名、十阶段、七项实验和重置确认头。
- Connected Playwright 校验真实 Compose 的重置、完整运行、八章、三端转交、实验协议、零外部请求和零浏览器告警，并保存 1440×900 全页证据。
- 页面不自行计算金融数字；格式化只改变显示单位，所有值来自 Demo API。
