# 外部设计样本取舍分析

读取时间：2026-08-04

完整阅读范围：awesome-design-md 的 IBM、Revolut、Linear 三份 DESIGN.md，以及 taste-skill 的 redesign-existing-projects 与 design-taste-frontend。

## 设计结论

项目不是三套品牌的拼贴。最终方向是“可信、克制、温和、数据准确的中国家庭财富工具”：以 IBM 的企业信息秩序为骨架，吸收 Revolut 面向普通金融用户的对象聚焦与触控尺度，吸收 Linear 的高密度表面层级和精细交互状态，再用项目自己的深蓝、品牌红、暖金与中文系统字体重构。

## IBM

借鉴：

- 4px 网格、稳定对齐和高密度企业信息秩序；
- 扁平表面、细分线和少阴影，适合顾问与风险端；
- 正文、表格、状态和焦点的明确层级；
- 48px 左右的触控目标和响应式折叠。

适用端：顾问端和风险端为主，客户端的数据明细也使用其表格纪律。

拒绝：

- 不复制 IBM Blue、IBM Plex 作为品牌签名、Carbon 页面结构或全直角语言；
- 不把营销页的浅灰分区直接套成复杂金融流程；
- 不依赖 Carbon 运行时包，因为项目需要自有组件和更温和的家庭语境。

转化：保留信息秩序和细分线，把主色改为低饱和深蓝，内部控件 6px、容器 10px，中文系统字体离线可用。

## Revolut

借鉴：

- 金融消费者界面的关键对象聚焦和高信任触控尺度；
- 适度圆角、清晰按钮层级和产品边界披露；
- 客户端渐进披露，让家庭先看到目标与下一步。

适用端：客户端、快速体验入口和未来规划书封面。

拒绝：

- 不使用真黑与白的强烈营销带切换；
- 不复制专有 Aeonik 字体、产品设备摄影、彩色产品插画或胶囊按钮体系；
- 不采用多种饱和强调色，也不用绿色暗示收益。

转化：把消费者友好感转为低饱和浅色界面、44px 以上触控目标和逐步解释，不引入任何 Revolut 品牌元素。

## Linear

借鉴：

- 高密度工作台的表面层级、细边界和克制强调色；
- 顾问/风险端的快速扫描、状态精度和紧凑控件；
- 8-12px 容器圆角、清晰 focus、active 和 disabled 状态；
- 数字与代码标识的稳定排版。

适用端：顾问端、风险端和深色高密度模式。

拒绝：

- 不复制近黑画布、薰衣草蓝、专有字体或以产品截图为主角的营销结构；
- 不把所有端都做成开发者工具；
- 不采用只有深色模式的方案。

转化：保留高密度层级和状态设计，改成系统浅色默认、深蓝品牌锚点和中文可读字号。

## redesign-existing-projects 的使用

仓库扫描时没有现有前端，因此无法列出旧页面中的 AI 模板、死链或可访问性回归。协议没有被跳过，而是记录为：Scan 为空仓；Diagnose 为缺少设计系统、状态、导航、响应式和无障碍；Fix 为建立 DESIGN.md、token、三端共享布局、错误边界、404、离线状态、focus、reduced-motion 与测试。详细证据见 client_ui_audit.md。

## design-taste-frontend 的使用边界

该技能明确不以 Dashboard、数据表和多步骤产品 UI 为目标。因此阶段 1 只使用它的 brief inference、反模板、交互状态和 pre-flight 检查；不采用 AIDA、随机布局、滚动劫持、重 GSAP 或电影化动效。核心三端始终服从本项目 DESIGN.md、金融合规和 WCAG 2.2 AA。

## Stage 9 转化记录

客户端完整体验继续采用“借鉴原则，不复制品牌”的方法：

- IBM 只影响 11 项任务的信息顺序、图表元数据、数据表和证据账本；没有引入 Carbon 组件、IBM 蓝或 Plex 字体。
- Revolut 只影响快速体检／深度规划的渐进披露、44px 触控目标和普通家庭语言；没有引入黑白营销带、设备摄影、彩色插画或胶囊体系。
- Linear 只影响深色模式的表面层级、任务选中态、紧凑状态和精确焦点；没有复制近黑画布、薰衣草色或开发者工具观感。

三者最终都被映射到 Fortune Copilot 自有 `tokens.css`。Stage 9 没有新增外部字体、图片、图标 CDN 或运行时设计依赖。`design-taste-frontend` 仅用于快速入口、报告封面和完整状态叙事的反模板检查，不覆盖账本、表格、多步骤金融流程和适当性证据的既有设计规则。
